# 编排与子 agent

> 判断稿不是一次写成的。编排器（本体，强模型）负责**立疑、派活、综合、销账**；
> 子 agent（弱模型）负责**读年报、查数据、返回发现**。
> 这是次新股小组本身的工作方式——分工，不是一个人一口气写。

## 产物存放（一个 run 一个文件夹）

```
reports/{SYMBOL}_thesis_{YYYYMMDD}/     ← 一个 run 一个文件夹（随 reports/ gitignore）
  report.md                             ← 成品（编排器写）
  疑惑.md                               ← 立疑清单（编排器 step2 写）
  findings/
    财务排雷.md                         ← 子 agent 各自写自己那份
    竞争.md
    尽调.md / 产业.md / 战略驱动.md
positions/{SYMBOL}.md                   ← 不在 run 文件夹里！跨 run 累积的耐久档案，单独跟踪
```

**写产物的硬规矩：一律用绝对路径。**

`reports/...`、`positions/...` 这类相对路径**不要**用来写文件。Bash 的工作目录跨调用保持，
而这个 skill 的流程里到处都是 `cd` 进 `lenses/`、`data/`、`findings/` 去读东西的动作——
cwd 会漂，而且漂了不会报错。

2026-08-18 实测：编排器读完 `lenses/核查.md`（cwd 停在 `lenses/`）之后，
用 `mkdir -p reports/{SYMBOL}_thesis_{日}/findings && cat > reports/{SYMBOL}_thesis_{日}/疑惑.md`
写立疑清单，整棵树被建进了 `.claude/skills/equity-thesis-cn/lenses/reports/` 下面。

三个放大因素让它一路漏到交付前：

1. **自检失效**——同一条命令末尾的 `wc -c reports/.../疑惑.md` 解析的是**同一个坏相对路径**，
   于是回报「写入成功、5512 字节」。**校验和写入在同一个坐标系里，校验就不可能发现问题。**
2. **缺失被掩盖**——真正的 `findings/` 是子 agent 建的（它们 cwd 在仓库根、prompt 里写死了路径），
   所以 run 文件夹看起来是齐的。
3. **git 看不见**——`.gitignore` 当时是非锚定的 `reports/`，匹配任意层级，走失的树对 `git status` 完全隐形。
   （已改为 `/reports/`。）

所以两条：**写文件用绝对路径**；**要核对写没写成，用与写入不同的坐标系去核对**——
写完之后 `ls` 绝对路径，而不是在同一条命令里 `wc -c` 同一个相对路径。
`check_thesis.py` 的硬约束 6 现在会兜住这一类失败，但那是最后一道门，不是第一道。

**为什么档案不进 run 文件夹**：假设记分板要连续多期演进，`positions/{SYMBOL}.md` 是"一个 symbol 一份、持续更新"的耐久记忆；塞进带日期的 run 文件夹会破坏这个本质。run 文件夹只装**本期产物**（成品 + 立疑 + 发现）。

**子 agent 自己写 findings 文件**：每个子 agent 把完整发现写到 `reports/{SYMBOL}_thesis_{YYYYMMDD}/findings/{名}.md`，再把发现返回给编排器。文件是耐久副本（编排器上下文被截断也不丢），返回值供综合。这样发现可追溯、可复查，不再只活在 transcript 里。

## 铁律：子 agent 产发现，编排器写散文

**子 agent 返回结构化发现 + 判断要点（bullet），绝不返回成稿散文。**

原因：五个子 agent 会产生五种口吻，而"统一的第一人称"是判断稿的质量标志。判断可以分布式产出（读了年报竞争章的子 agent 最有资格判断竞争格局），但**声音必须由编排器集中写**。

每个子 agent 的返回格式统一为：

```
## 发现（事实，带出处）
- <事实>（来源：年报 p.XX / aggregate.json 字段）

## 判断要点（bullet，不写成段）
- <一句话判断> —— 依据：<哪条发现>
- 不确定：<明确说不知道的地方>

## 建议进档案
- 假设：<可被后续证伪的陈述>
- 未决疑问：<答不出来的>
```

编排器拿到这些 bullet 后，用统一口吻把它们改写成正文的「观点总结」段，并对开篇疑惑清单销账。**子 agent 的 bullet 不直接进报告。**

## 子 agent 花名册（深度在各自的指导文件里，不在这里）

每个子 agent 的方法论深度落在一份**指导文件**里；编排器派活时不再把 prompt 写在这里，而是让子 agent **去读那份文件并遵循**。这样五个 lens 各自可独立加厚、独立维护。

| 子 agent | 覆盖节 | 指导文件 | 时序 |
|---|---|---|---|
| 财务排雷 | 4 财务全景表 | `.claude/skills/financial-redflags-cn/SKILL.md`（独立 skill，也可单独调用） | 并行 |
| 竞争 | 7 竞争格局 | `.claude/skills/equity-thesis-cn/lenses/竞争.md` | 并行 |
| 尽调 | 1/2/3 简介·股权·高管 | `lenses/尽调.md` | 并行 |
| 产业 | 5/6 行业空间·商业模式 | `lenses/产业.md` | 并行 |
| 战略驱动 | 8/9/10 募投·战略·驱动 | `lenses/战略驱动.md` | 并行 |
| **核查** | 不覆盖节，校验全部 findings | `lenses/核查.md` | **串行，五份 findings 到齐后** |

**核查为什么必须串行**：它的输入是另外五份 findings，逻辑上不可能与它们同时跑。它不是第六个视角，是第六道**工序**。

## 派活方式（统一模板）

对每个子 agent，`subagent_type: general-purpose`，派活 prompt 用同一个模板填空：

```
你是{角色}子 agent，只做一件事：对 {SYMBOL}（{公司名}，估值原型：{原型}）做{领域}分析，返回发现、不写报告。

先完整读 {指导文件} 并严格遵循它——读什么、做哪些动作、输出什么格式都在里面。
数据在 data/{SYMBOL}/，年报 PDF 用 Read 的 pages 参数读。
把完整发现写到 reports/{SYMBOL}_thesis_{报告日}/findings/{名}.md，再把发现按指导文件的格式返回给我。
你的返回是数据，不是成稿散文。
```

要点：
- **findings 落盘由你（编排器）保证**：收到每个子 agent 的返回后，立刻用 Write 把返回原样写进 `reports/{SYMBOL}_thesis_{报告日}/findings/{名}.md`。返回值你一定拿得到，不要指望子 agent 自己写文件——round2 实测子 agent 常常没写成，findings/ 空了编排器就被迫自己刨年报。五份 findings 到齐才进综合。
- **{估值原型}** 由编排器在立疑阶段判定（见 `framework.md` 的"按估值原型调整重心"，15 个原型的定义见 `valuation_archetypes.md`），随派活传给每个子 agent——这样财务排雷会用对阈值、产业会用对 TAM 口径。
- **生产环境**子 agent 自动跑在 flash 上（`CLAUDE_CODE_SUBAGENT_MODEL`）；**开发模拟**时显式 `model: sonnet`。
- 指导文件是**文件路径读取**，不依赖子 agent 能不能用 Skill 工具——最稳的集成方式。

## 步骤 3.5：核查（五份 findings 到齐后、综合之前）

**这一步不可跳过。** 派活模板：

```
你是核查子 agent。任务很窄：核实 {SYMBOL}（{公司名}）findings 里最承重的数字，
逐条抄原文给我。不要写报告、不要发挥、不要 WebSearch。

先读 lenses/核查.md 并遵循它。
待核对的 findings 在 reports/{SYMBOL}_thesis_{报告日}/findings/ 五份。
年报 PDF 在 data/{SYMBOL}/annual_pdf/（近 3 年都在，往期用于跨期核对）。

输出：每条给「结论一句话 + 原文抄录 + 页码」。查不到就写"未披露/未查到"，
并区分**公司没披露**与**我没查到**——这两者对判断的含义完全不同。
```

**编排器在派核查之前，自己先挑出 5–8 条"承重数字"**——即"如果这个数错了，某一节的判断方向就会反过来"的数。挑不出来就说明还没读懂 findings。

核查回来后：**就地修正 `findings/*.md` 里的错处**（标一行"（YYYY-MM-DD 复核修正）"），并在正文末尾留一节「数据核查记录」，列出改了什么、改前改后。改动过程要留痕，不能悄悄改掉。

### 为什么加这道工序（实测依据）

300633 那次跑，五份 findings 里有**两个数字是错的，且都会改变判断方向**：

| 项 | findings 首轮 | 年报实际 | 若不核出的后果 |
|---|---|---|---|
| 子公司净利润 | +7,876 万 | **−7,875.81 万**（负号排版中单独占行）| 正文会印出"投入期硬件业务净利率 69.7%"这个不可能的数 |
| 子公司营收/净利 | 2,753 万 / 529 万 | **2.75 亿 / 5,285.66 万** | 把一条已盈利 0.53 亿的产品线误判成仍在烧钱 |

两处都是**子 agent 读表读错**，不是编造。`check_thesis.py` 这类结构校验器**拦不住**——它检查的是有没有观点总结、档案更没更新，不检查数字对不对。当时是靠"70% 净利率不可能"这个常识矛盾临时拦下的。**一个靠运气的拦截点，必须变成一道工序。**

## 综合阶段（编排器自己做，不外包）

**综合的唯一输入是 findings/*.md 五份（已按步骤 3.5 核查修正）+ 疑惑.md + 核查子 agent 返回的「已核实清单」+ 参照系/（步骤 3.6 补参照系的产出，写开篇参照系声明块要用）**（取估值数字可另读 aggregate.json）。年报的重活子 agent 已经替你做完并浓缩进 findings——**这一步不要再打开 annual_pdf、不要 pdftotext/grep 年报、不要 WebSearch**。某份 findings 太薄，补派那个子 agent，别自己去刨。

拿到五份 findings 后，编排器：

1. **写全文散文**，包括每节「观点总结」。观点总结是把子 agent 的"判断要点"用**统一第一人称**改写成段，不是复制 bullet。数字已在数据段出现过，观点段指向它即可，不重复罗列。
2. **销账**：对步骤 2 立的每条疑惑，用"现在回答开篇的问题 N："回收；答不出的进档案「未决疑问」。
3. **估值/赔率/评分**（framework.md 第十一、十二节）——需要全局视角，不外包给子 agent。估值先按估值原型选方法（例：成长渗透型→前瞻 PE 三情景；周期加工型→穿越周期 P/B；亏损未验证型→PS + 现金跑道，具体见 `valuation_archetypes.md`），再做三情景。
4. **写回档案**（position_file.md）：把各子 agent 的"建议进档案"汇总成假设记分板、未决疑问、变更日志。

综合阶段是判断稿真正的价值所在。子 agent 只是把编排器从"读几百页年报"里解放出来，好让它专注判断。
