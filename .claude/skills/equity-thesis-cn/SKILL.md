# A 股判断稿生成器（次新股小组框架）

## 这份 skill 产出什么

**判断稿**，不是数据稿。两者并存，各有各的用途：

| | `equity-report-cn`（数据底稿） | `equity-thesis-cn`（本 skill） |
|---|---|---|
| 结构由谁决定 | 模板槽位 | 开篇的疑问清单 |
| 数字的角色 | 内容本身 | 服务于某个判断 |
| 对财报口径 | 采信 | 质疑并重算 |
| 出口 | 三情景目标价 | 五维评分 + 字母评级 + 赔率区间 |
| 语气 | 无人称、逐句 `[H/M/L]` | 第一人称、敢下负面判断 |
| 跨期 | 每次从零重推 | 读档案 → 更新 → 写回 |

需要资金流、龙虎榜、十大股东、券商共识这类全量数据覆盖时，用 `equity-report-cn`。本 skill 的数据取自同一条流水线，但只挑用得上的。

## 核心契约：每节三段

**这是本 skill 最重要的一条，也是它和数据稿的根本区别。**

正文每一节都由三段组成，顺序固定：

```
**详细资料/数据：**
事实与数字。表格放这里。

**细节补充：**
口径修正、一手信息、同业与竞对对照。确实没有就写"无"。

**观点总结：**
第一人称判断。回答两件事——这一节让我对公司的看法改变了什么，
以及我还不确定什么。
```

**「观点总结」写的是判断，不是数据复述。** 判断所依赖的数字已经在第一段出现过了，这里指向它即可（"上面那条 56% 的毛利率"），不重新罗列。这一段读起来应该像一个人在说话。

三段式的作用是把事实和判断在物理上分开。一节写完，如果「观点总结」删掉后信息没有损失，说明这节没做判断，重写。

## 执行流程

### 步骤 0：读档案（先于一切）

```bash
cat positions/{SYMBOL}.md    # 不存在则本次为建档
```

档案格式与更新规则见 `position_file.md`。档案里有四样东西必须带进本次写作：

1. **上期的估值锚与理由** —— 本期倍数若与上期不同，必须在正文写明为什么；给不出理由就沿用上期。
2. **假设记分板** —— 上期列的假设，逐条核对兑现 / 证伪 / 待定。
3. **未决疑问** —— 上期没答出来的问题，本次优先尝试。
4. **人工注入区** —— 用户手写的调研纪要、一手价格、专家观点。**与流水线数据冲突时采信这里**，并在正文标注来源与日期。

### 步骤 1：确保数据就位（幂等——已有有效数据就跳过采集）

先校验现有数据，**通过就直接进步骤 2，不必重采**：

```bash
python3 tools/validate.py <SYMBOL>     # 纯 stdlib，不需要 .venv
```

- 退出 `0` = 数据齐且有效 → **跳过采集**，进步骤 2。（数据被预先放好/软链时走这条，无需 .venv——sda-dev 开发测试即此情形。）
- 退出 `1` = 数据缺失/不全 → 采集后再校验：
  ```bash
  .venv/bin/python tools/run_pipeline.py <SYMBOL> && python3 tools/validate.py <SYMBOL>
  ```
  `run_pipeline` 需要装了 akshare 等依赖的 `.venv`（生产环境有；纯 dev 环境没有的话，得先把 `data/{SYMBOL}/` 备好再跑本 skill）。

数据层是仓库根的共享 `tools/run_pipeline.py`（不属于任何 skill，直接调脚本，不经由其他 skill），产物落在 `data/{SYMBOL}/`，**近 3 年**年报 PDF 在 `data/{SYMBOL}/annual_pdf/`（`annual.json` 的 `annual_reports` 列出每期的年度、日期与本地路径；`annual_meta` 仍指最新一期）。**生产日常若要强制刷新数据，先删 `data/{SYMBOL}/` 或手动跑 run_pipeline。**

**往期年报是用来跨期核对的**——商誉减值的性质、借款用途、分部口径重分类、激励目标的历史达成，这些问题只有最新一期时一律卡在"缺上一年年报无法核实"。子 agent 遇到需要跨期比对的问题，直接读 `annual_pdf/` 下的往期 PDF。

> **产物存放**：一个 run 一个文件夹 `reports/{SYMBOL}_thesis_{YYYYMMDD}/`，内含 `report.md`、`疑惑.md`、`findings/{子agent}.md`。跨 run 累积的档案 `positions/{SYMBOL}.md` 不进 run 文件夹。布局详见 `orchestration.md`。

### 步骤 2：立疑（编排器亲自做）

**先看财务全景，再立疑。** 顺序很要紧：人工底稿的疑惑是看完报表之后从数字里逼出来的，不是从主营业务描述里憋出来的。

读完数据与档案，在派任何子 agent 之前，列 **2–4 条疑惑**，写入 `reports/{SYMBOL}_thesis_{YYYYMMDD}/疑惑.md`。

**疑惑要是"决策形状"的，不是"审计形状"的。** 判据：这个问题的答案会不会直接改变我买不买。

开立那份人工底稿只立了两条，都是决策级的：

> 1. 内窥镜是否可以再创造一个开立的规模？
> 2. 彩超业务是否可以恢复正常增速 15% 左右？

对照一组**审计形状**的反例——它们是好的排查项，但不该占据疑惑清单：
"利润为什么塌了""毛利率去哪了""现金为什么是负的"。这些是**派活清单**，写进给子 agent 的 prompt 里，不写进疑惑清单。

一条好疑惑通常长这样：**"这家公司的<某条业务线>能不能<达到某个量级/增速>？"**——它可证伪、有量级、且答案直接决定估值。

写完检查一遍：如果某条疑惑无论答"是"还是"否"，我的结论都不变，删掉它。

这份清单是全文的脊椎，也是给子 agent 派活的依据——每条疑惑指向某个子 agent 去查。后面所有节都在还这笔债。

### 步骤 3：派子 agent（并行，读年报的重活外包）

按 `orchestration.md` 的花名册派子 agent。每个子 agent 的方法论深度在各自的**指导文件**里（财务排雷 → 独立 skill `financial-redflags-cn`；其余四个 → `lenses/*.md`），派活时让子 agent 去读那份文件并遵循。**子 agent 把完整发现写进 `findings/{名}.md`，并返回结构化发现 + 判断要点（bullet），绝不返回成稿散文**——五个子 agent 会有五种口吻，声音必须由编排器集中写。

**立疑阶段判定的估值原型，派活时传给每个子 agent**（见 `framework.md` 开篇原则三）——这样财务排雷用对阈值、产业用对 TAM 口径、估值选对方法。派活模板、返回格式全在 `orchestration.md`。开发模拟时子 agent 显式 `model: sonnet`，生产自动跑 flash。

**收到每个子 agent 的返回后，你立刻把它的完整返回原样写进 `reports/{SYMBOL}_thesis_{YYYYMMDD}/findings/{名}.md`**（用 Write）。不要依赖子 agent 自己写文件——你收到的返回值一定拿得到，落盘由你保证。五个 findings 文件到齐，才进步骤 3.5。

**本 skill 里所有写文件的动作一律用绝对路径**（`疑惑.md`、`findings/*.md`、`report.md`、档案都算）。流程中频繁 `cd` 进 `lenses/`、`data/` 读东西，cwd 会漂且不报错，相对路径写出去的产物会静静落在别处——实测发生过，原委与防线见 `orchestration.md` 的「写产物的硬规矩」。

### 步骤 3.5：核查（串行，不可跳过）

五份 findings 到齐后、下笔之前，派**核查子 agent**（指导文件 `lenses/核查.md`）把承重数字回原文核实一遍。

**编排器先自己挑出 5–8 条"承重数字"**——"如果这个数错了，某一节的判断方向就会反过来"的数。挑不出来说明还没读懂 findings。

核查回来后：就地修正 `findings/*.md`（改处标"（YYYY-MM-DD 复核修正）"），并在正文末尾留一节「数据核查记录」，列明改了什么、改前改后。**改动要留痕，不能悄悄改掉。**

**核查返回的最后一张「已核实清单」不要丢掉——步骤 4 写稿时要逐个数字对照它**（见下方「数字纪律」）。写稿写到一半发现某个要用的数字不在清单里，就回来补派一次核查，把它加进清单。**这道工序可以跑不止一次。**

**为什么这道工序是硬的**：300633 实测，五份 findings 里有两个数字读错——一个正负号读反（+7,876 万实为 −7,875.81 万），一个数量级差 10 倍（2,753 万实为 2.75 亿），两处都会翻转所在节的判断方向。`check_thesis.py` 检查的是结构（有没有观点总结、档案更没更新），**不检查数字对不对，拦不住这类错误**。详见 `orchestration.md`。

### 步骤 3.6：补参照系（串行，核查之后、成稿之前）

核查子 agent 已经给每个承重数字归了一次类（五档，见 `lenses/核查.md`）。凡落在
「私有基准」或「无参照系」两档的，都还悬空——它们没有同口径的外部比较对象，而结论
可能正压在它们上面。**编排器从核查返回的「已核实清单」里筛出这些条目**（核查子 agent
按契约不落盘、直接返回，所以悬空清单以这次返回为准，不是去读某个文件），派一个
**补参照系子 agent**去逐条接地。

**这是整条流水线里唯一允许联网（WebSearch）的子 agent**。理由：核实标的公司自己的
数字不需要联网——`data/{SYMBOL}/` 与年报已经够；需要联网的只有一件事：外面的同业/
同板块现在把这类资产定价在什么水平。边界因此画得很窄：**只查别人，不查标的公司自己
的任何数字**，标的自己的数字仍旧只能由其他子 agent 从 `data/{SYMBOL}/` 和年报取。这条
边界可用 `tools/audit_overreach.py` 事后审计（它专门检测"查自己"这一类越权）。

**总是派出这一步**，哪怕这一轮一条悬空的都没筛出来——筛不出悬空条目时，子 agent
空转返回（不落盘）就是合法结果，不要因为"感觉这轮数字都还行"就跳过这个步骤本身。

三条护栏，写进派给它的任务里，一条都不能省——这些是结构性要求，不是叮嘱：叮嘱"记得
留痕""别查错人"这类话本身拦不住越权或编造，必须让缺项/越界本身导致这条产出被打回：

1. **联网所得必须带 url + 逐字原文（verbatim）+ 抓取日期**，三者缺一项，这条参照系
   就不算完成，要求它补齐或改判「无参照系」，不许留空硬凑。
2. **只查别人，不查自己**——标的公司自己的数字不进它的查证范围，这条由
   `tools/audit_overreach.py` 事后审计。
3. **外部数不许自动升到最高档「外部·可回溯」**：同一个数要 ≥2 个独立来源交叉对得上，
   或者本来就来自本地数据层（如 `peers_curated.json` 的中位数），才给「外部·可回溯」；
   只有一个来源给「外部·单源未交叉」；口径对不齐（含"宽池子且池内无同品种"）给
   「外部但口径存疑」；找不到就如实给「无参照系」——**找不到是可接受的结果，编一个不是**。

落盘到 `reports/{SYMBOL}_thesis_{报告日}/参照系/补.md`（先 mkdir -p，一条都没接上时可以
不落盘），一行一条：`- [强度] what ｜ 值 ｜ 出处 ｜ 取数日`（分隔符是全角竖线 ｜），联网
条目下一行缩进补 `    > 原文：<逐字片段>`。**what 用词原样沿用核查返回里的写法**，
一个字都不要改——步骤 4 写开篇参照系声明、以及交付前的硬门都按这个串精确匹配，
改了就等于这条没接上。

### 步骤 4：综合成稿（编排器亲自做，不外包）

**你综合的唯一输入是 `findings/*.md` 五份（已按步骤 3.5 核查修正）+ `疑惑.md` + 核查子 agent 返回的「已核实清单」。** 这五份 findings 已经是子 agent 把几百页年报读完、浓缩出的成品——年报的活它们做完了。你只读 `findings/` 和 `data/{SYMBOL}/aggregate.json`（后者仅供取估值用的行情/财务数字）。

**数字纪律**：写稿时每个承重数字，先看核实状态，再看参照系强度——两条纪律独立判断，
互不替代。

核实状态，**只有三个合法出口**：

| 情形 | 怎么办 |
|---|---|
| 在「已核实清单」里 | 直接用 |
| 在 findings 里但没核过 | 可以用，正文标一句「未核实」 |
| **你不放心、又非用不可** | **补派一次核查子 agent**（`lenses/核查.md`），把这个数加进清单 |

**第三条是关键：你对某个数字不放心时，正当出口是再派一次核查，不是自己去查。**

参照系强度，核查子 agent 已经给每个数字归了一档（五选一，见 `lenses/核查.md`）：

| 参照系强度 | 怎么办 |
|---|---|
| 外部·可回溯 | 直接用 |
| 外部·单源未交叉 / 外部但口径存疑 | 可以用，正文标注来源限制 |
| 私有基准 / 无参照系 | **不得当已证实的事实用**；若结论压在它上面，必须降级措辞，且开篇要写参照系声明 |

「外部但口径存疑」里若注明"宽池子且池内无同品种"，**不得据此算成"是中值的 N 倍"这类
偏离度**——03858 实测这样算错了一个数量级（见 `lenses/核查.md` 的实测依据）。

**一个数可以"确认无误"（核实状态没问题）却仍是「私有基准」（参照系强度不行）**：
03858 那一轮五条承重数字全部核实通过，但没有一条够得上「外部·可回溯」，判断照样
悬空——两条纪律要分开过，任何一条不过都不能直接把数当尺子用。

补派一个窄任务的核查子 agent 很便宜；自己去核很贵——**2026-08-19 实测：编排器在派出核查子 agent 之后，
又自己把核查做了一遍（`pdftoppm -r 400` 渲染年报页看图、`grep` 年报全文核数字），
把剩余预算全部耗尽，`report.md` 根本没写出来。** 同一只票连续两轮都栽在这里。

所以，综合阶段**不要自己碰年报，也不要联网**。包括这条绕路：
**先 `pdftotext` 把年报导到 `/tmp/xxx.txt`、再对那个文件 `grep`/`sed`/`awk`，一样算自己刨年报**——
实测这条绕路占了越权调用的近一半，而且它不触发任何按路径写的禁令。
判据不看路径，看**内容**：只要你正在读的是年报正文（无论它此刻叫什么文件名），就已经越界了。

某份 findings 太薄或缺关键数，补派**那一个**子 agent；数字存疑，补派**核查**子 agent。两条路都通，别自己上手。

拿到五份 findings 后，编排器统一口吻写全文到 `reports/{SYMBOL}_thesis_{YYYYMMDD}/report.md`：

- **开篇结论**（`framework.md` 第〇节，150–250 字）：一句话给公司定性 + **价值判断归结为核心两点**（必须两点，逼自己排序）+ 一句核心风险。敢把利空放第一句。写完检查它和第十二节的决定性变量对不对得上。
- **参照系声明块**——紧跟在开篇结论散文之后。**只要 `reports/{SYMBOL}_thesis_{报告日}/参照系/` 目录存在**（步骤 3.6 补参照系落过任何一份文件），交付前的硬门（`check_thesis.py` 硬约束 7）就会真的拦这一块，格式不对不许交付；步骤 3.6 一条都没接上、没落盘时，`参照系/` 目录不存在，硬门这一项会跳过（向后兼容），但只要落过一份文件就必须按下面的格式写：
  - 用一个 `> **参照系声明**` 引用块，逐条写明核心两点各压在哪个数上、该数的参照系强度是什么。**块内每一行都要以 `>` 开头，中间不许留空行**——硬门的正则在第一个不以 `>` 开头的行处截断这个块，中间空一行会让后半块整个作废，连带把已经写对的声明判成没写。
  - 点名承重数字时，**原样引用 `参照系/` 文件里的 what 串、并用「」括起**——硬门按这个串精确匹配，写别的说法、或泛泛一句"部分数据未经外部验证"都匹配不上。
  - 若某数参照系强度是「私有基准」或「无参照系」，**降级措辞必须与那个 what 写在同一句里**（"无法回答"/"未取得"/"绝对口径下"之一）——硬门按**就近**判定（按句号/问号/感叹号切句），降级句甩到块尾、不挨着对应的 what，不算数。
  - **凡强度属「私有基准」「无参照系」、且其 what 串、或长度 ≥6 的 value 串字面出现在声明块之前的开篇散文里的条目，都必须在声明块里点到名**——漏一条就拦，点名另一个安全数字替代不了。
- 按 `framework.md` 十二节骨架，每节走三段式。固定问句是**菜单不是清单**——挑与本公司判断相关的深答，其余明确跳过并交代一行理由。
- **多产品线公司必做三分法**（`framework.md` 第五节）：每条线归入 基本盘 / 第二曲线 / 第二曲线储备，并让第十一节的情景表按这个分类拆。
- **观点总结**用统一第一人称，把子 agent 的判断要点改写成段，不是复制 bullet；数字已在数据段出现，指向即可。
- **销账**：对步骤 2 每条疑惑用"现在回答开篇的问题 N："回收；答不出的进档案「未决疑问」。允许答不出，不允许假装没问过。
- **估值/赔率/评分**（`framework.md` 十一、十二节）：给市值区间不给目标价；**三情景要拆到产品线，不能只做公司层面**；倍数先列同业历史区间与中位数再取值，别拍；查税收优惠到期年份；赔率给区间、精度到十位数、并折成"几年一倍"；概率没把握就写"我判断不了"；**五维均分映射到 A/B/C 三档**（B+/B− 是修饰符不是档位，用了要说明哪一维拉偏）；决定性变量写成**正反两栏**并给行动触发条件。
- **末尾留一节「数据核查记录」**：步骤 3.5 改了哪些数、改前改后、错误类型，以及仍未弥合的口径差异。改动要留痕。

不限总字数，但观点段合计不应少于数据段的三分之一（校验器会查）。

**长度上的提醒**：人工底稿（开立那份）正文只有 19 页，其中大半是表格与截图，散文部分很精炼。"不限字数"是给判断留空间，**不是鼓励把数据段堆厚**——超长时砍数据段，不砍观点总结。

### 步骤 5：写回档案

更新 `positions/{SYMBOL}.md`（格式见 `position_file.md`）：评分、评级、估值锚及变更理由、假设记分板、可证伪点触发、未决疑问、变更日志。汇总各子 agent 的"建议进档案"。

**`最近更新` 必须等于本次报告日**——校验器据此判断本步是否真的执行了。

### 步骤 6：校验（硬门）

```bash
.venv/bin/python tools/check_thesis.py <SYMBOL> reports/<SYMBOL>_thesis_<YYYYMMDD>/report.md
```

退出码 `1` = 硬约束违反（缺观点总结 / 档案没更新 / 残留目标价 / 缺销账 / **run 文件夹缺 `疑惑.md` 或 findings 不足 5 份**），**必须回去修，不得交付**。`2` = 软警告（观点段偏薄），提示但可交付。`0` = 通过。

### 步骤 7：不要跑 PDF

`tools/md_to_pdf.py` 输出路径硬编码到**生产目录**。在 `sda-dev` 开发时跑它会污染真实报告。需要 PDF 时由用户在生产目录触发。

## 强制约束

1. **零编造**：数字来自 `data/{SYMBOL}/` 或年报 PDF 或档案的人工注入区。三者都没有就写"我没查到"——像人工报告那样直说（"从各种渠道上查不到取消的原因"），不要留空表格。

2. **每节必须有观点总结**，且观点总结是判断不是复述。

3. **倍数不许无理由变动**：本期估值锚与上期不同时，正文和档案变更日志都要写明理由。

4. **假设先回check再写新的**：上期假设未逐条核对，不得列本期假设。已被证伪的假设若本期仍保留，必须解释为什么。

5. **一手输入优先**：档案人工注入区的信息与流水线冲突时采信前者，正文标注"（一手，YYYY-MM-DD 调研）"。

5b. **公司说的和我推的必须分开**。引用公司口径（年报表述、调研纪要、管理层指引）之后，如果下一句是自己的外推，**要用一个明确的字眼把它标出来**——"推断""判断""我们假设""我们预计"都行，关键是读者一眼能看出交界在哪。底稿的做法：澜起引公司"可能还需要两三年的积累"，接"**判断**在未来 5 年内有望成为同等量级的产品"；中控每段都是"根据 ARC 报告，2019 年国内 SIS 市场规模为 3.2 亿美元 → **我们假设**未来 10 年实现 90% 国产化 → **预计** 2023 年国产化市场空间达 2.5 亿美元"；石基"**推断**是软件的收入模式从'软件授权+维护合同'转换成 SaaS 模式"。**不标的后果是把自己的假设伪装成公司的披露**——读者要么全信要么全不信，没法只对那半句提出异议。与第 1 条（零编造）不同：这一条管的不是数字来源，是**判断的归属**。

6. **口径存疑就重算**：费用率跨公司对标前，先检查分部结构是否可比（例：研发费用率应剔除硬件营收后再算）。重算了就在「细节补充」里写明原公式、新公式和差异。

7. **不给买入/卖出评级，不给股价目标位**。出口是五维评分 + 字母评级 + 赔率区间 + 一个决定性变量。这是买方入池语言，不是卖方荐股语言。

8. **同一个事实允许有两种方向相反的读法，两面都写，不要强行统一**。五份人工底稿全部这么干过：澜起——市场只有 6 亿美元，**对成长性是坏事，对竞争格局是好事**（弱化了外部进入动机），两面都讲；开立——同一笔高销售费用，第五页读作"吞噬公司所有的利润"，第十八页读作"提前布局、费用前置"；中控——结论直接并排两句矛盾判断"从商业模式上看不算好的标的，但是他是具有稀缺性的"；乐鑫——产品单一是风险，但"物联网属于方兴未艾的领域，目前还不太需要担心"（先记账、暂不扣分）。**强行统一会丢信息；矛盾本身可以就是结论**（中控那份的结论正是"生意不好但值得占位"）。写法上把两种读法明确并排，各自给依据，最后说明**在本次判断里采信哪一种、为什么**——或者明说两种都成立、因此这一项不进评分。**不允许的是只写对自己结论有利的那一种读法。**

## 语气

第一人称，有立场，敢写减分项。"我认为""我判断""我都不明白""我就不敢猜了"都是合适的。

避免"或将""有望""值得期待"这类无责任措辞——它们看起来严谨，实际上没承担任何判断。宁可写"我认为大概率可以持续，因为……"，也不写"有望持续"。

不用 emoji。金额单位、CY 口径、前复权、语气等见本 skill 自带的 `style_guide.md`（自含，不依赖其他 skill）。
