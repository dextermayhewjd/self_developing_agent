# Codex 研究方法校准

用五份人工底稿对照原生判断稿方法，产出诊断报告、十二节乘五篇矩阵、原文抽查记录及逐条 before/after 修改建议。**只输出建议，不自动改研究方法。** 用户后续逐条采纳才执行相应修改。

先读 [calibration_protocol.md](calibration_protocol.md)，它包含完整的盲抽、归纳、规则测绘、对撞、抽查方法及判据。确定本技能真实路径所属仓库根，然后使用确定性执行器运行完整流程：

```bash
node <仓库根>/tools/run_codex_workflow.mjs calibrate-equity-thesis --date <YYYYMMDD> --root <仓库根>
```

日期取用户指定值或当天。默认原始 PDF 位于 `/home/hongshi/ work_document/模板报告（之前的文件）/`，首段含前导空格，命令必须整体引用该路径。用户另给来源时通过执行器的 `--args-file` 传递配置。安装/控制流检查使用同一命令加 `--check`，不启动真正校准。

执行器检查 `evidence/` 的五份动作清单和 `methods.md`：六份全部齐备才整体复用盲抽与归纳；缺任何一份则完整重建五份动作清单和方法。仅依赖底稿的证据持久保存于本技能 `evidence/`；随研究方法变化的规则、对撞、抽查、报告与修改建议属于本次 `reports/calibrate_<YYYYMMDD>/`。

隔离必须由执行阶段落实：盲抽只给 PDF，归纳只给内联动作记录，规则测绘只给研究规则，对撞等待两边齐备，抽查回原始 PDF。根会话不代替这些阶段做判断或向盲阶段透露被审计规则。工作进程不能递归运行本技能。

提案条件不可省略：新增要求至少三篇适用底稿支持；删除要求适用范围内零命中且分母至少三篇；分母为零判为本样本无从检验；其余弱支持只列候选。新增与删除均须原文抽查，区分「底稿确实没做」「我没找到」「不在适用域」。

持续跟进执行器及落盘，不把阶段启动或摘要当作完成。交付前逐项核对协议末尾自检清单；报告明确写出“样本仅五篇”和“本轮校准不能证明后续运行更好”两个限制。返回报告、矩阵、抽查记录和 patches 路径，并说明未自动应用建议。

Codex 文件/终端工具承担读写，PDF 文本用 `pdftotext -layout`，表格/截图用 `pdftoppm` 后查看图像。遵循当前权限；原始底稿只读，所有输出使用绝对路径。
