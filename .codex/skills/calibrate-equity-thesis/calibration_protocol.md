# 校准研究方法的完整协议

## 为什么需要它

`equity-thesis-cn` 的方法论派生自 5 篇人工底稿，但**这层派生关系从未被复核过**。已知它至少犯过一次可查证的过拟合——`framework.md` 自己记录：

> 曾经按单一样本（3.4→B）外推出一张五档表（A/B+/B/B−/C），第二份底稿直接证伪了它。这是个教训：用一个观测点固化映射表，得到的是伪精度。

一次被抓到，说明这类错误是**结构性**的而非偶发。本 skill 把那次抓捕系统化，回答两个问题：

1. 5 篇底稿是否都符合 12 节骨架的分析逻辑？
2. lenses 里哪些是单一样本外推（该降级）、哪些是底稿在做而 lenses 没写（该补）？

## 与 debug-equity-thesis 的分工

| | debug-equity-thesis | calibrate-equity-thesis（本 skill） |
|---|---|---|
| 审什么 | **行为**——编排器跑得对不对 | **方法论**——skill 教的东西对不对 |
| 方法 | 隔离跑一遍 + 审计转录 | 底稿盲抽 + 规则对撞 |
| 出口 | 已知偏离清单 + 改法 | 诊断报告 + before/after 改写稿 |

两者接力：本 skill 修**教什么**，debug 验**执行成什么样**。改完 lenses 之后应当再跑一次 debug，否则不知道改动有没有真的让行为变好。

## 两条天花板

**必须在报告里写明，不许含糊过去：**

1. **判定不了"改完之后跑得更好"。** 那是行为问题，归 debug-equity-thesis。
2. **上限就是这 5 篇底稿。** 若 5 位作者集体存在盲区，本 skill 只会看到"0/5，不该写进 lens"，无法发现该盲区。补那个要靠底稿之外的来源，不在射程内。

### Codex 完整执行链

确定性执行器依次保证五份盲抽、独立归纳、独立规则测绘、统一对撞、独立原文抽查和诊断/改写稿落盘。规则测绘可与盲抽/归纳并行；归纳前必须取得五份盲抽；对撞必须等方法和规则都到齐；抽查必须取得对撞判定；最终提案以抽查结果为准。

各阶段把完整材料写入执行器指定的绝对路径，结构化 schema 校验结果，执行器核对落盘后交给下一阶段。盲阶段只看指定 PDF；归纳阶段只获得内联序列化的五份动作清单，不通过含被审对象名称的路径取材料。临时路径属于本次运行，不能用全局固定目录。阶段不递归调用 workflow 或另外派生 agent。

修改盲抽/归纳模板后，词汇隔离检查同时覆盖本协议和原生 workflow 中实际运行的提示词。

### 隔离墙的原理（先读这里，否则后面两道工序会写坏）

**污染的入口是提问的抽象层级，不是禁令。**

问"这篇用了哪些方法论"，模型会去够它已知的方法名，于是**只认得出 skill 里写过的东西**——象限②（遗漏）当场清零，整个 skill 白做。
问"第 7 页这位作者做了什么"，它只能照着页面说。

`debug-equity-thesis` 一次实测显示禁令无效：round2 加了"分工边界"禁令，越权调用反而从 257 升到 299。**所以隔离靠的是提问方式，不是靠写"不许看 skill"。** 禁令仍然写，但它是第二道保险，不是第一道。

**隔离区有两处，改动任何一处之后都必须重跑词汇 lint：**

1. 本文件里被两组 `<!-- ISOLATED-PROMPT-START/END -->` 注释包起来的段落（派活模板，供人读）
2. `.codex/workflows/calibrate-equity-thesis.mjs` 里的 `blindPrompt` 与 `inducePrompt`（实际执行的那两段）

两处都不得出现 `equity-thesis-cn` 的任何专有构造词。**真正执行的是第 2 处**——
第 1 处是模板，改了模板而没同步脚本，等于没改。

lint 的四项判据（缺一不可）：与被审计 skill 的 ≥8 连续汉字重合、命中其章节标题、
命中其加粗术语、命中专有词表，**四项都必须为零**。

一类**不算污染**的重合要会分辨：底稿原文自己用的词。例如"基本盘/第二曲线/储备"
出自澜起底稿 p9 原句，`framework.md` 的三分法本就是从那里抄的——
归纳产物里出现这些词，方向是「底稿 → skill」而不是「skill → 子 agent」，不构成泄露。
判据是回底稿查那句原文在不在。

### 工序 2 · 规则测绘（1 个子 agent，可与工序 1/1.5 并行）

输入：`equity-thesis-cn/writing_contract.md`、`framework.md`、`lenses/*.md`、`financial-redflags-cn/SKILL.md`。**不给底稿。**

输出 `rules.md`，每条：

```
R-{来源}-{序号}  一句话摘要
出处   {文件}:{行号}
原文   「逐字抄的规定性语句」
适用域 {无条件 / 条件：{六项客观属性之一}}
适用域理由 {一句话，附出处}
形态   {方法型 / 例子型 / 伪方法}
```

**适用域的「条件」必须用工序 1 记录的六项客观属性之一来表述**（产品线数量 / 是否周期性行业 / 报告期内是否盈利 / 有无并购史 / 是否多分部经营 / 是否有海外收入）——这样工序 3 才能与 `evidence/methods.md` 里同样六选一的适用域机械匹配。表述不出来的记「无条件」，但仍要写一句出处理由说明为什么判定为无条件。

**什么算规定性语句**：含"必须/要/应当/不许/固定/一律"的句子；以及无这些词但实际在规定动作的句子（如"每节挑 2–4 个深答"）。纯背景描述不计。

### 工序 3 · 对撞（独立统一判断阶段）

对撞由一个阶段统一完成，避免把同一规则的适用域、支持度和提案条件分给多个彼此隔离的判断过程。

**动作一：四象限。** 把 `evidence/methods.md` 的 `D'` 与 `rules.md` 的 `R` 对齐：

| | 底稿在做 | 底稿不做 |
|---|---|---|
| **skill 有写** | ① 已固化 | ③ **过拟合 / 无源之水** |
| **skill 没写** | ② **遗漏** | ④ 不管 |

②③ 是否真的生成 patch，由后面「判据」里各自的门槛决定，这里只是分类。

**动作二之前先取矩阵的行**：对撞阶段读 `equity-thesis-cn/framework.md`，抄出十二节（一至十二）的标题作为矩阵的行——该文件里第〇节「开篇结论」不计入十二节，单独处理，不进矩阵。本动作的输入是 `evidence/{代号}.md` 五份（工序 1 的产物），不回头再读 PDF。

**动作二：12 节符合度矩阵**（回答问题 1）。判据是**该节的分析动作有没有发生**，不是有没有同名章节、不是顺序对不对。三档：

- **做了** — 该节要回答的问题，底稿实质回答了（哪怕散落别处、标题完全不同）
- **未做** — 没有对应的分析动作
- **不适用** — 该节对这家公司无意义（如单一产品线公司的产品三分法）

分母只算「做了 + 未做」。**某节若在适用篇里支持度 ≤ 1/2，那是骨架过度规范化的证据，结论指向 `framework.md` 而不是 lenses。**

### 工序 4 · 抽查（1 个子 agent，串行，出改写稿之前）

**只查会触发 lens 写操作的判定**：

| 象限 | 会否改 lens | 抽查 |
|---|---|---|
| ② 遗漏 → 新增 | 会 | **要** |
| ③ 过拟合 → 删/降级 | 会 | **要** |
| ① 已固化 → 不动 | 否 | 不查 |
| ④ 双方都无 | 否 | 不查 |

按**是否触发写操作**划线，不按象限直觉划线：误判过拟合会删掉好方法；误判遗漏会往 lens 里加一条假方法、污染此后每一份报告。**两类误判代价对称，都要查。**

抽查方式：回到"据称支持/不支持"的那几篇底稿原文复核，逐条抄页码与原文，明确区分三档——「底稿确实没做」「我没找到」「该篇不在适用域内，本不该计入分母」。这是 `equity-thesis-cn/lenses/核查.md` 那道工序的同构物。

## 判据

### 支持度：分母是适用域内的篇数

```
支持度 = 该方法命中的篇数 / 适用域内的篇数
```

**分母不是恒定的 5。** 否则"周期股用穿越周期 P/B"这类只对周期股成立的规则，会被 1/5 误判成过拟合。适用域标签分两处产出：`rules.md` 里的规则由工序 2 标注，`evidence/methods.md` 里的方法由工序 1.5 标注（见工序 1.5 输出里的「适用域」栏）；两边都只能用工序 1 记录的六项客观属性来表述，与工序 1 记录的「标的客观属性」机械匹配——不要临场拍。

**适用域内篇数为 0 时**，支持度无定义：判「本次样本无从检验」，不进入四象限、不生成 patch。这种情况常见于被审计规则按盈利状态/资产类型分叉、而 5 篇底稿的标的恰好都落在同一档的时候——分母是 0 不代表规则错，只代表这次样本测不出来，绝不能因此把它当过拟合删掉。

5 篇一人一票，等权。

### 形态三分（这是"不要过度依赖具体例子"的可执行版）

| 形态 | 定义 | 改写方向 |
|---|---|---|
| **方法型** | 说清了怎么做，换一家公司照样执行 | 升格进正文 |
| **例子型** | 只给了"某篇怎么做的"，换家公司无从下手 | 降级为脚注/附录 |
| **伪方法** | 看着像方法，实为单一样本外推 | 删除，或降级为"待更多样本" |

**不是删例子。** 是把例子和它想教的方法拆开，让方法能独立站住；拆完例子留作佐证。判据很简单：**把例子那几行遮住，剩下的字还够不够一个没读过底稿的人照着做？** 不够就是例子型。

### 象限②的入 lens 门槛

需 **≥ 3 篇适用底稿支持**才生成改写稿。只有 1–2 篇的记为「候选」，写进报告但**不生成 patch**。

这道门槛防的是：5 篇是不同作者的小组作业，质量未必齐，单篇独有的做法可能是个人习惯甚至坏习惯，不该被当成方法学进 lens。

### 象限③的删除门槛（与象限②对称）

象限② 要 ≥3 票才出新增 patch，象限③ 不能反过来一票不要就出删除 patch——那样两类误判的代价就不对称了。门槛：**适用域内 0 命中，且分母（适用域内篇数）≥ 3，才生成删除 patch**；分母不足 3 的，或命中数恰为 1 的，都只记「疑似过拟合·候选」，写进报告但不出 patch。

```
           建议按「方法升格、例子降级」重排，内容不变。
```

编号 `R-{来源}-{序号}`；改写稿一一对应 `P-{来源}-{序号}`，便于逐条采纳（"采纳 P-产业-03 与 P-竞争-01，其余不动"）。

**`报告.md` 三块**：
1. 12节 × 5篇 符合度矩阵（答问题 1）
2. 四象限总表（答问题 2）
3. 抽查记录（哪些判定被复核、有无翻案）

**`patches/{目标文件}.md`**：每条给 before / after 原文块 + 一句改写理由 + 挂靠的规则号。

**处置权：诊断 + 改写稿，不自动修改方法正文。** 报告与 patches 正常落盘，修改建议由人逐条挑选后再应用到 `lenses/`。理由：判过拟合用的是 5 票支持度，N=5 极小；一条规则拿 1/5，可能是过拟合，也可能只是另外 4 位作者没想到——两者形状相同，只有人能分。自动改写等于把这个判断交给投票，而那正是本 skill 要治的病。
