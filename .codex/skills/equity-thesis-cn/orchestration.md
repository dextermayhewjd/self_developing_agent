# Codex 判断稿执行合同

本文件描述 `.codex/workflows/equity-thesis.mjs` 与 `tools/run_codex_workflow.mjs` 的实际分工。阶段是隔离的 `codex exec` 工作进程；结构化返回用于调度，完整研究材料通过文件传递。

## 顺序与职责

1. **准备数据与档案**：执行器校验数据。退出 0/2 继续，退出 1 时采集后再校验；仍缺核心数据则停止。既有档案和人工输入参加本次研究。
2. **盘点与立疑**：盘点已有产物；立疑阶段先读财务全景、档案及估值原型，再写 2–4 条能改变决策的疑惑，首行标明估值原型。
3. **五条研究管道与板块基准并行**：每个方向独立完成「挖掘 → 核查」，该方向 findings 到位即核查，不等待另外四方向。板块基准同时按当前主营、必比口径和可比性筛选形成同业比较。
4. **补参照系**：全部核查完成后读取全五份核查，逐条补齐悬空的外部比较；保留出处、原文、取数日与强度，找不到如实保留限制。
5. **独立成稿**：完整读取疑惑、五份 findings、五份核查和全部参照系，按写作合同统一口吻。仅估值数可另读 aggregate；不重挖年报、不联网。
6. **host 审查任务**：研究 workflow 仅输出初稿.md。host 建立 report.md 与 v2 Store；独立审查完整十二节/五路/全部附件并返回原始 Review。host 分配稳定 RT ID，worker 仅返回 Proposal，host 独占应用。局部包最多 UTF-8 32 KiB / 两个目标节，局部提案、完整修订与最终独立审查分别沿用问题修订、修订成稿、成稿审查的冻结配置。任务关闭只能由完整独立审查裁定。默认累计两轮修订 / 三次有效完整审查；CLI --review-max-rounds N 为绝对总上限（1..10），保留既有消耗与历史。
7. **交付**：机器核对当前报告/物理证据/ledger/receipt → 暂存档案 → 硬门 → 暂存 PDF → host 提交。报告硬门错误进入同一任务与轮次预算，独立复审后重过门；纯档案/PDF 重试不花语义轮数。每次发布前验证同一 receipt，人工冲突保留原文件。未关闭阻断、活跃批次或停止原因均禁止交付。

## 文件交接

```text
reports/{SYMBOL}_thesis_{YYYYMMDD}/
  疑惑.md
  findings/{财务排雷,尽调,产业,竞争,战略驱动}.md
  核查/{财务排雷,尽调,产业,竞争,战略驱动}.md
  参照系/{板块基准,补}.md
  初稿.md                 # writer 输出；host 才能建立/修改 report.md
  report.md
  成稿审查.json
  .codex-workflow/          # 状态、冻结配置、阶段 prompt、事件与结果
positions/{SYMBOL}.md     # 跨期耐久档案
reports/pdf/{SYMBOL}_thesis_{YYYYMMDD}.pdf
```

所有产物写到仓库根计算出的绝对路径。**研究工作进程负责写完整研究文件，执行器核对产物与结构化摘要；审查/提案/转录工作进程只读并返回 JSON，报告与 ledger 由 host 应用**；父会话不拿摘要重建全文。核查可以修正对应 findings，但必须留下可追溯记录。文件不齐、内容为空或审查不绑定当前稿不能视作成功。

模型和推理强度由执行器解析并保存到运行配置，不使用其他平台的模型别名。模型与强度按字段解析：CLI 覆盖 → stages 完整标签/同类前缀 → 脚本阶段提示 → 文件 default → 冻结有效默认；切换模型且未指定强度时采用该模型的目录默认强度。只有 equity-thesis 的盘点、peer-comparability 的盘点和读配置显式提示 low；其余阶段（含问题修订、修订成稿、成稿审查）没有脚本强度提示，沿用上述冻结解析结果。问题修订是合法阶段名，stages.问题修订.effort=high 仅覆盖局部提案，不改变成稿审查；CLI 覆盖仍优先。阶段独立上下文通过文件接力，不继承父会话的研究结论。工作进程不能再次调用总 workflow 或自行派生 agent。

读写用 Codex 文件/终端工具，PDF 用 `pdftotext` 和必要的 `pdftoppm` 图像核对。核查限定本地原件；补参照系只查外部比较对象，不重查标的自身。成稿、审查和修订不联网、不重挖原始文件。边界审计用：

```bash
node <仓库根>/tools/audit_codex_workflow.mjs <运行目录>
```

审计结果是可观察的行为证据；日志缺失、匹配不到某条命令或机器检查通过，都不能当作事实真值或研究质量的保证。

候选稿与原始输入清单完整时，续跑直接恢复审查，不因缺档案或旧阶段失败重跑研究。needs_evidence/no_safe_edit 保留未决；原始证据变化或人工改稿报冲突，不自动采用。旧 v1 仅诊断，不自动导入。Store HEAD 指向不可变 commits/ledgers/reviews/receipts；显示 JSON 不能当 authority。操作与二进制证据核验见 [原生操作说明](../../../docs/codex-workflow.md)。

### 输入来源与全文修订的恢复边界

研究生产阶段在 backend 派发前由 host 把作用域、原始输入摘要和既有派生字节备份原子写入 input-manifest.json 的 producers。并行独立阶段允许登记在飞作用域内的变化，但成稿、审查、硬门及交付只接受全部阶段已结算且摘要匹配的数据。中断续跑先校验原始、未知和越界路径；仅对登记作用域保留中断字节至恢复历史并恢复已结算备份，标记阶段必须重跑。每次恢复的 generation 进入阶段缓存键，盘点也不能把 pending 阶段当成完成。后续人工改动与恢复日志不符时保留冲突字节并拒绝恢复。

同一代码的新报告日仅从既有 native v2 清单接受 stage/path/hash 与当前字节完全一致的来源记录，并记录原清单摘要；旧清单不改写，旧研究结论不复用。不登记的文件、已完成阶段之后的修改继续阻断。生命周期恢复在既有 symbol/run 锁内、旧 v1 只读诊断之后、指纹接受之前执行。普通续跑不重新采用原始输入；显式 --reset 才在恢复旧活动生产阶段后允许重新取数并建立新原始基线。

host 给完整审查和统一修订提供冻结的 writing_contract、framework、style_guide 和五路 lens 方法全文、各文件摘要及完整语义覆盖规则；缺失或与冻结方法冲突就拒绝派发。局部提案仍使用有界上下文。full_revision 的 section:0 授权精确修改第一节前的开篇，局部提案禁止 section:0。第一节直接从字节0开始时，可用完整第一节标题作为唯一非空 boundary anchor；after 必须原字节保留该标题为结尾，只在其前插入开篇，仍验证全部十二节边界。审计分别报告 physical evidence validity 与 pending independent rereview；历史审查不会替代修补后的新独立审查。
