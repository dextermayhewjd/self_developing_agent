# Smart commit

迁自 Claude 的 `/smart-commit`，在 Codex 中使用 `$smart-commit`。本文件可独立执行，不读取原命令或依赖 Claude。

## 盘点与分批

1. 读取适用的 `AGENTS.md`、仓库提交约定、README 和测试配置。核对当前分支、upstream、已有本地 commit，以及整个暂存区；保留他人的改动和暂存内容。
2. 用 `git status --short`、`git diff --stat` 和未跟踪文件清单盘点。目录只用于初步归类；以功能和依赖确定提交边界。代码、对应测试、必需资产和配置同批，确保 checkout 后可用。独立文档、数据归档及与功能无关的重构另批。
3. 少量同主题变更可以一次提交；跨主题或超过十个路径时评估分批。不要为了满足目录数量机械拆分。报告、底稿和对应档案按标的归档，不混入工程改动。
4. 每批列出中文 message、修改原因、精确路径白名单、验证方式和排除项。先检查路径及内容，跳过未授权的凭证、本地配置、抓取原文、数据和超大文件；遵守项目对自撰研究稿的入库规则，不因它属于报告目录就一律排除。不用 `--force` 添加忽略项。

## 授权与验证

- 尚未获得提交授权：先展示具体方案并确认。用户已经确认该方案：直接执行，不重复确认。用户明确追加新要求时，把直接实现该要求的文件列入更新清单并说明归属；其他超出已批准清单的变更或目的分支实质改变时再确认。
- 推送需要明确授权的远端和分支。已经获得该授权则在验证完成后执行；尚未授权则完成本地提交后询问一次。提交授权不自动包含推送、PR 或合并。
- 从项目配置找测试命令，验证当前候选提交。用索引树导出或隔离快照检查实际将提交的内容，不能依赖下一批未暂存文件使测试通过。失败先处理；找不到测试命令则如实说明。记录命令、结果和已有警告；只有代码、测试、相关配置、资产、依赖和验证环境均未变时才复用已验证结果，纯文档批次检查对应链接、结构和文件完整性即可。

## 精确提交

每批使用具体路径，不使用 `git add .`、`git add -A` 或宽泛父目录。目录改为符号链接时，暂存**该链接自身的精确路径**及目标资产；Git 会同时记录旧目录内受跟踪文件的删除。不要暂存穿过新链接的旧子路径，也不要为处理一个链接而添加整个 `.agents`。

例如一份已获批准的目录替换：

```bash
git add -- .agents/skills/example .codex/skills/example/SKILL.md
git diff --cached --name-status
git diff --cached --check
```

将**整个暂存区**与本批预期的新增、修改、删除集合比对，包括链接的 `120000` 类型及其目标；不符时先查明，不清空其他人的暂存。验证后用 `git commit --file <message-file>` 提交，多行 message 通过文件保留原文。

message 用“新增 / 更新 / 修复 / 重构 / 文档 / 配置 / 清理: 原因明确的一句话”，可补充两三行依据和实际验证。沿用用户 Git 身份；不复制固定的 Claude 署名，不编造模型邮箱，不改全局身份。

提交失败或 hook 报错时保留现场，检查原因；修复后创建新 commit，不自动 amend。保持既有历史，不自行 rebase、reset、清理工作区或强推。

## 推送与汇报

核对远端分支和将推送的 commit 范围，按已有授权执行普通 `git push <remote> <branch>`。拒绝推送时先检查远端变化，不以强推重试。成功后核对远端 SHA 与本地 HEAD 一致。

汇报技能入口、各批 commit、测试结果、远端分支和剩余本地文件。没有运行的验证或没有完成的推送要明确说明。
