## 一、要解决的问题

`equity-thesis-cn` 的方法论来自 5 篇人工底稿，但**这层派生关系从未被复核过**。已知它至少犯过一次可查证的过拟合——`framework.md` 自己记录：

> 曾经按单一样本（3.4→B）外推出一张五档表（A/B+/B/B−/C），第二份底稿直接证伪了它。这是个教训：用一个观测点固化映射表，得到的是伪精度。

一次被抓到，说明这类错误在系统里是**结构性**的而非偶发。本 skill 把这次抓捕系统化：拿 5 篇底稿当 ground truth，反向审计 skill 的每一条规定，并回答两个问题——

1. 5 篇底稿是否都符合 12 节骨架的分析逻辑？
2. lenses 里有哪些是从单一样本外推的（该降级），有哪些是底稿在做但 lenses 没写的（该补）？

## 五、架构与产物分层

```
.claude/skills/calibrate-equity-thesis/
  SKILL.md                    ← 单文件起步：入口 + 五道工序 + 判据 + 自检清单
  evidence/{代号}.md          ← 持久，入库。5 篇底稿的动作清单（工序 1）
  evidence/methods.md         ← 持久，入库。跨篇方法清单 D'（工序 1.5）
                                 二者只有新增底稿时才重跑

reports/calibrate_{YYYYMMDD}/ ← 一次 run 的产物，随 /reports/ gitignore
  报告.md                      ← 12节符合度矩阵 + 四象限总表 + 抽查记录
  rules.md                     ← 规则清单 R1…Rn（工序 2 产出）
  patches/{目标文件}.md        ← before/after 改写稿，逐条编号
```

`D'` 也进持久层，因为它是 5 篇 PDF 的**纯函数**——归纳 agent 不看 skill，所以 lenses 怎么改都不影响它。复审时从工序 2 起跑即可。

**为什么 evidence 与 run 分层**：93 页底稿的内容不会变，变的是 lenses。把最贵的一步（读 PDF）做成最常做的一步是浪费。抽出 `evidence/` 后，**lens 改动后的复审从工序 2 起跑**，工序 1 与 1.5 全部跳过，PDF 一页不用再读。

判定分层归属的准则很简单：**只依赖底稿的产物入持久层，依赖 skill 现状的产物入 run 文件夹。** 工序 1、1.5 只看底稿 → 持久；工序 2、3、4 都要看 skill 当前的样子 → 一次性。

**为什么 evidence 放 skill 目录内而非仓库根**：它是方法论参考资料（性质近 `framework.md`），不是项目数据（`positions/` 那种）。放 skill 内则 skill 自足可搬，仓库根不为窄用途多一个顶层目录。

**为什么单文件起步**：`equity-thesis-cn` 是长到 1,286 行才拆的。本 skill 预计 ~200 行，现在拆是过度工程。真长起来再拆。

## 六、五道工序

```
   ┌─ 工序1   盲抽 ×5（并行，一篇一个）  只给 PDF，不给 skill
   │            ↓
   ├─ 工序1.5 归纳 ×1                    只给 5 份动作清单，不给 skill
   │            ↓
   └─ 工序2   规则测绘 ×1（与 1/1.5 并行）只给 skill，不给底稿
                ↓
        工序3   对撞（编排器亲自做）
                ↓
        工序4   抽查 ×1（串行）
                ↓
        报告.md + patches/（编排器写）
```

### 工序 1 · 盲抽（5 个子 agent 并行）

- **输入**：一篇 PDF。**不告知 `equity-thesis-cn` 存在**，prompt 内不出现其任何词汇（三段式、观点总结、三分法、五维评分、疑惑、lens、基本盘/第二曲线……）。
- **任务框成描述性而非分析性**：记录"这位作者在第 X 页做了什么动作"，而不是"找出这篇的方法论"。
- **输出**每条动作：`动作 + 页码 + 原文或表格摘录 + 该动作服务于什么判断`。最后一栏是让工序 1.5 能把动作抽象成方法的钩子。
- **顺带记录标的客观属性**：产品线数量、是否周期性行业、是否盈利、有无并购史、是否多分部。纯事实、不含方法论词汇，不破隔离墙；工序 3 据此机械匹配适用域。
- **落盘由编排器保证**：收到返回后编排器自己 Write 到 `evidence/{代号}.md`（沿用 `equity-thesis-cn` 的既有教训，不指望子 agent 自写）。

**隔离墙的原理**：污染的入口是**提问的抽象层级**，不是禁令。问"有哪些方法论"，模型会去够它已知的方法名，于是只认得出 skill 里写过的东西；问"这一页作者做了什么"，它只能照着页面说。`debug-equity-thesis` 已验证 prose 禁令无效（round2 加禁令后越权调用从 257 升至 299）。

### 工序 1.5 · 归纳（1 个子 agent）

- **输入**：5 份动作清单。**同样不给 skill。**
- **输出**：跨篇方法清单 `D'`，每条 = `方法陈述 + 哪几篇在做 + 各自页码`。
- **为什么必须独立成一道工序**：编排器已通读过 `equity-thesis-cn`，由它做"动作→方法"的抽象，会不自觉地抽象成 skill 已有的形状，使象限②（遗漏）静默塌进象限①（已固化）。而象限②是问题 2 的全部答案。编排器第一次接触"方法"这个抽象层级，必须是在 `D'` 与 `R` 都已成型之后。

### 工序 2 · 规则测绘（1 个子 agent，与工序 1/1.5 并行）

- **输入**：`equity-thesis-cn/SKILL.md`、`framework.md`、`lenses/*.md`、`financial-redflags-cn/SKILL.md`。**不给底稿。**
- **输出**：规则清单 `R1…Rn`，每条 = `规定性语句原文 + 出处(文件:行) + 适用域 + 形态`。
- **什么算规定性语句**：含"必须/要/应当/不许/固定/一律"的句子；以及无这些词但实际在规定动作的句子（如"每节挑 2–4 个深答"）。纯描述性背景不计。

### 工序 3 · 对撞（编排器亲自做，不外包）

把 `D'` 与 `R` 对齐成四象限，算支持度，并产出 12节×5篇 符合度矩阵。

**12 节「符合」怎么判定**（这一条不定义清楚，矩阵会变成数标题）：判据是**该节的分析动作有没有发生**，不是有没有同名章节，也不是顺序对不对。三档取值：

- **做了** — 该节要回答的问题，底稿实质回答了（哪怕散落在别处、标题完全不同）
- **未做** — 没有对应的分析动作
- **不适用** — 该节对这家公司无意义（如单一产品线公司的产品三分法）

分母同样只算「做了 + 未做」，不适用的不计票。**某节若在适用篇里支持度 ≤ 1/2，那是骨架过度规范化的证据，结论应指向 `framework.md` 而不是 lenses。**

不外包的理由与 `equity-thesis-cn` 的综合成稿一致：判断须由一个脑子统一做，否则口径会散。

### 工序 4 · 抽查（1 个子 agent，串行，出改写稿之前）

**覆盖所有会触发改写的判定**，即象限②与③；象限①④不查。

| 象限 | 会否改 lens | 抽查 |
|---|---|---|
| ② 遗漏 → 新增 | 会 | **要** |
| ③ 过拟合 → 删/降级 | 会 | **要** |
| ① 已固化 → 不动 | 否 | 不查 |
| ④ 双方都无 | 否 | 不查 |

两类误判代价对称，都是对 lens 的写操作：误判过拟合会删掉好方法；误判遗漏会往 lens 里加假方法，污染此后每一份报告。所以按**是否触发写操作**划线，不按象限直觉划线。

抽查方式：回到"据称支持/不支持"的那几篇底稿原文复核，逐条抄页码原文。这是 `lenses/核查.md` 那道工序的同构物。

## 七、判据

### 支持度：分母是适用域内的篇数

```
支持度 = 该方法命中的篇数 / 适用域内的篇数
```

分母**不是恒定的 5**。否则"穿越周期 P/B"这类只对周期股成立的规则会被 1/5 误判成过拟合。适用域由工序 2 给出标签、工序 1 记录的客观属性机械匹配。

5 篇一人一票，等权。

### 形态三分

| 形态 | 定义 | 改写方向 |
|---|---|---|
| **方法型** | 说清了怎么做，换一家公司照样执行 | 升格进正文 |
| **例子型** | 只给了"某篇怎么做的"，换家公司无从下手 | 降级为脚注/附录 |
| **伪方法** | 看着像方法，实为单一样本外推 | 删除，或降级为"待更多样本" |

**不是删例子**——是把例子和它想教的方法拆开，让方法能独立站住；拆完例子可留作佐证。这是"不要过度依赖具体的例子"的可执行版。

### 分母为 0 的处置（2026-08-19 最终评审补）

5 篇底稿是 5 家已盈利的次新股。`framework.md` 里按盈利状态/资产类型分叉的规则（周期股穿越周期 P/B、重资产 EV/EBITDA 等），适用域内篇数可能是 **0**。此时支持度无定义，而四象限只有「在做/不做」两行，规则会直落象限③被删掉——把正确规则删掉。

**加第五种判定：适用域内 0 篇 → 「本次样本无从检验」，不入象限、不生成 patch。** 工序 4 抽查的分档同步加这一档（原本只有「底稿确实没做」与「我没找到」）。

12 节矩阵早已有「不适用」这个逃生口，规则侧必须有对应物，否则两套判据不对称。

### 象限③的对称门槛（2026-08-19 最终评审补）

原设计只给象限②设了 ≥3 票门槛，象限③一票不要就能生成删除 patch——这与"两类误判代价对称"的论证自相矛盾。

**象限③同样设门槛：适用域内 0 命中且分母 ≥3 才生成删除 patch；1 命中记为「疑似过拟合·候选」，写进报告但不出 patch。** 两侧的 patch 生成条件必须对称。

### 象限②的入 lens 门槛

需 **≥3 篇适用底稿支持**才建议写进 lens；单篇独有的做法只记为"候选"，不生成改写稿。这是防止把某一篇的坏习惯当方法学进去。

## 八、产出格式

**规则判定卡**：

```
R-产业-03  三分法（基本盘 / 第二曲线 / 第二曲线储备）
出处       lenses/产业.md:18
形态       方法型
适用域     多产品线公司 → 适用 4/5 篇（乐鑫单一产品线，不计票）
支持度     3/4
象限       ① 已固化
判定       保留。lens 现有表述中例子占三行、方法占一行，建议按
           「方法升格、例子降级」重排，内容不变。
```

编号 `R-{来源}-{序号}`，改写稿一一对应 `P-{来源}-{序号}`，便于逐条采纳（"采纳 P-产业-03 与 P-竞争-01，其余不动"）。

**报告.md 三块**：12节×5篇 符合度矩阵（答问题 1）→ 四象限总表（答问题 2）→ 抽查记录（哪些判定被复核、有无翻案）。

**patches/**：每条给 before / after 原文块 + 一句改写理由 + 挂靠的规则号。

## 九、处置权

**诊断 + 改写稿，不自动落盘。** 由人逐条挑选后再落到 `lenses/`。

理由：判定过拟合用的是 5 票的支持度，N=5 极小。一条规则拿 1/5，可能是过拟合，也可能只是另外 4 位作者没想到——两者形状相同，只有人能分。自动改写等于把这个判断交给投票，而那正是本 skill 要治的病。

## 十、失败模式与对策

| 失败模式 | 对策 |
|---|---|
| 盲抽 agent 被 skill 词汇污染 | 降抽象层级 + prompt 零 skill 词汇 + 不告知其存在 |
| 编排器污染归纳步骤 | 工序 1.5 独立成道，归纳早于对撞 |
| PDF 表格抽不出 | `pdftoppm -r 300` 转图再读 |
| 适用域判错导致分母错 | 适用域标签须给理由；客观属性由工序 1 事实记录 |
| 单篇的坏习惯被当方法 | 象限② ≥3 票门槛 |
| 页码/引文编造 | 工序 4 抽查，逐条抄原文 |
| 复审时重读 PDF 浪费 | `evidence/` 持久层，工序 1 可跳过 |

## 十一、验收测试

**冒烟用例（现成的 ground truth）**：`framework.md` 自记的"3.4→B 外推出五档表"是一个**已确认的伪方法**。本 skill 跑完若未将其标为伪方法/低支持度，说明判据失灵。这是免费的回归用例，写进 SKILL.md 的自检清单。

**结构自检（清单，不写脚本）**：
- 每条判定带页码
- 每条改写挂规则号
- 每条象限② ≥3 票
- 12节矩阵的 5 列都非空

**为什么现在不写 `check_*.py`**：本 skill 跑得不频繁。等它跑到第三次仍在犯同类错误，再固化成脚本——与仓库既有做法一致（`check_thesis.py` 的硬约束都是实测踩过之后才加的）。

## 十二、实现边界

本设计的**实现**只包含一件事：写出 `.claude/skills/calibrate-equity-thesis/SKILL.md`。

`evidence/` 是这个 skill 的**首次运行产物**，不是实现的一部分。两者分开的理由：SKILL.md 是可以审阅、可以改的文本；evidence 是跑出来的数据，它的质量取决于 SKILL.md 写得好不好。先把 skill 写对，再跑第一次，用冒烟用例（见第十一节）检验跑出来的东西对不对。

所以实现计划到 SKILL.md 落盘 + 冒烟用例写进自检清单为止；第一次实跑是随后的独立动作。

## 十三、不做什么（YAGNI）

- 不自动改写 `lenses/`
- 不写校验脚本
- 不拆多文件
- 不做"复现测试"（跑 skill 重写底稿标的再比差异）——差异混杂数据差异、模型能力差异、方法论差异，归因不了；且"跑一遍看行为"的生态位归 debug-equity-thesis
- 不引入底稿之外的方法来源（教科书、卖方深度）——那会破坏 ground truth 的单一性，是另一个 skill 的事
