# 可比性台账（Peer Comparability）设计

日期：2026-08-27
状态：设计已确认，待写实施计划
触发：上一个项目（参照系接地）交付后，03858 的板块坐标仍然拿不到——骨架和门建好了，喂给它的料只有 PE/PB/PS

---

## 一、问题陈述

### 上一轮解决了什么、没解决什么

「参照系接地」把诊断接成了控制流：宽池不许算倍数、开篇压私有基准不许交付、失败大声报错。但基金经理最初的问题——**「这只票在板块里算什么水平」**——仍然答不了。

原因在实测中很清楚：`valuation_archetypes.md` 为耗竭资源型定义的必比口径是 **P/NAV 中位数、EV/资源吨、EV/单位年产能、C1 成本曲线分位**，而 `discover_peers.py` 只算得出 **PE/PB/PS**。**零重叠。**

### 探针（2026-08-27）挖出的三件事

**一、可比性是三层的，我此前只做了一层。**

拿 A 股四家「钨业同业」验证：

| | 品种 | 业务性质 | 披露制度 | 实情 |
|---|---|---|---|---|
| 章源钨业 002378 | ✓ | ✓ | ✓ | 有矿，年报 p.17 明确「钨(WO3)保有资源量 7.41 万吨」 |
| 厦门钨业 600549 | ✓ | ✓ | ✗ | 有矿，但只给产能 12,000 吨/年，未披露资源量 |
| 中钨高新 000657 | ✓ | △ | ✗ | 柿竹园采矿权 2024 年底才注入，主业硬质合金 |
| 翔鹭钨业 002842 | ✓ | **✗** | — | **无自有矿山**，年报只引 USGS 全球数 |

**只有 1 家真正可比。** 而我在上一个项目里拿这四家算出「PE 中位数 33.23、03858 是 2.82 倍」——**这是同一个错误的更细一层**：原报告错在「池子里没有钨」，我错在「池子里有钨但不是矿」。

**二、口径可不可得，由披露制度决定，不由努力程度决定。**

两家年报「单位成本 / 吨成本 / 现金成本 / 完全成本 / 采选成本」**命中数为 0**。不是抠得不细：

- 章源的营业成本按**要素**分（原材料 92.40% / 人工 1.11% / 能源 1.00% / 折旧 1.06%），无产品维度；
- 章源年报 p.745 明写「公司自产钨精矿**全部自用**」——不外销就没有销售成本行；
- 厦钨分产品表最细到「钨钼等有色金属」（收入 167.5 亿 / 成本 123.1 亿），混着精矿、APT、钨粉、硬质合金、钼产品，是冶炼加工全链条口径。

**中国钨业公司的成本披露是「加工企业」口径，不是「矿山」口径。这是业务性质决定的会计事实。**

而 TSX / ASX / AIM 上市的矿企受 **NI 43-101 / JORC** 强制，技术报告必须披露储量、品位、C1、AISC。**所以成本曲线分位不是拿不到，是样本找错了地方。**

**三、可得的那部分，成本极低且立刻有价值。**

探针 20 分钟算出了原报告完全没有的一个板块坐标：

```
章源钨业  市值 301.7 亿 ÷ 钨保有 7.41 万吨 = 40.7 万元/吨 WO3
03858    市值 247.6 亿 ÷ 资源  22.4 万吨 = 11.1 万元/吨 WO3
                                  03858 / 章源 = 0.27 倍
```

**方向与原报告的「贵」相反。** 两者可同时成立（03858 资源量大但品位低、NPV 相对市值低；章源市值含加工业务），而这恰恰说明单一口径不可靠、必须多口径并列并标注各自限制。

## 二、设计约束（承袭 + 新增）

承袭上一个项目：

1. **不可人工穷尽的必须动态**——不接受手工维护同业名单或分类表。
2. **错误的参照系比没有参照系更危险**——形式合规实则不可比的东西不触发警报。
3. **失败要么被拦住、要么被大声记录，不能静默。**
4. **fail-closed**：宁可零召回，不给噪声。

本项目新增：

5. **N 是一等产物**，不是中位数的附注。
6. **「拿不到」要区分制度性缺失与个案未披露**——前者换样本才有用，后者换一家可能就有。

## 三、关键决策

| # | 决策 | 取舍 |
|---|---|---|
| D1 | 核心产物是**可比性台账**，不是同业名单或中位数 | 03858 最有价值的输出是「A 股只有一家真正可比」，那是任何中位数都表达不了的 |
| D2 | 第二层判定**反向套用原型表已有的 `归属判据`** | 零新增手工配置；15 个原型自动覆盖；也修正了「同品种 ≠ 同原型」这个我此前漏掉的层 |
| D3 | 第三层「披露制度」**运行时推导 + 缓存**，不预先手写 | 约 60 个条目但按需生长；缺条目时大声报错不静默退化 |
| D4 | 台账**按品种存**，不按标的存 | 钨板块的台账对所有钨矿标的成立，第二篇报告成本近零 |
| D5 | `N < 3` 时**禁止出现「中位数」三字** | 用「中位数」包装 N=1 就是本项目要消灭的伪装 |
| D6 | 独立 workflow，可单跑也可被 `equity-thesis` 内联调用 | 「钨板块有几家真正可比」本身是有价值的问题 |

## 四、组件 1：可比性台账

产物形如：

```
品种：钨（折 65% WO3 精矿）        原型：耗竭资源型
候选 6 家 → 三层判定 → 可比 1 家

代码    名称      市值     品种  业务性质  披露制度   判定      依据
600549 厦门钨业  835.4亿   ✓     ✓        ✗(储量)   部分可比  年报仅给产能12000吨/年，无资源量
000657 中钨高新 1435.7亿   ✓     △        ✗(储量)   部分可比  柿竹园采矿权2024末注入，主业硬质合金
002378 章源钨业  301.7亿   ✓     ✓        ✓         可比      年报p.17「钨(WO3)保有资源量7.41万吨」
002842 翔鹭钨业  121.3亿   ✓     ✗        —         不可比    无自有矿山，年报仅引USGS全球数
600397 江钨装备    —       ✗     —        —         不可比    主营矿山装备，非钨生产
688778 厦钨新能    —       ✗     —        —         不可比    电池正极材料

可得口径：EV/资源吨 (N=1)
不可得口径：C1成本曲线分位 —— 制度性缺失（A股钨企成本按要素分、
            自产精矿全部自用无销售成本行）
```

**三条硬规矩：**

1. **指标只在通过判定的集合上计算**，不是先算再打标签。
2. **`N < 3` 禁用「中位数」**，强制改写为「唯一可比样本」或「N=2 的两点区间」。
3. **每格判定必须可回溯到原文行**，「不可比」旁边要写能被推翻的依据。

## 五、组件 2：三层可比性判定

| 层 | 问的是 | 判据来源 | 淘汰示例 |
|---|---|---|---|
| ① 品种 | 它产不产这个东西？ | 主营描述 | 江钨装备造矿山装备 |
| ② 业务性质 | 它持有的资产跟标的同类吗？ | 年报 | 翔鹭无矿 |
| ③ 披露制度 | 它被强制披露我要的口径吗？ | 上市地 + 行业监管 | A 股无矿山单位成本 |

### 第二层的泛化：反向套用 `归属判据`（D2）

原型表每段已有 `归属判据` 字段，此前只用来判标的。**把它套在候选身上就是第二层：**

```
耗竭资源型 · 归属判据：主要资产有可枯竭的储量，产出为同质大宗商品，售价外生
  → 翔鹭钨业：无自有矿山 ✗
  → 章源钨业：三个采矿权 + 披露 WO3 保有 7.41 万吨 ✓
```

判据是**「候选是否也属于这个原型」**。15 个原型的归属判据已写好，本层因此自动覆盖全部原型。

这一层还修正了一个概念错误：**同品种 ≠ 同原型**。翔鹭产钨（第一层过），但它的资产是加工产能不是储量，属周期加工型。

### 第三层的泛化：口径 → 制度 缓存（D3）

「这条口径由什么制度强制」是**口径的属性，不是公司的属性**——约 60 个条目，按需生长：

```json
{
  "C1/AISC 成本曲线分位": {
    "强制制度": ["NI 43-101（加拿大）", "JORC（澳大利亚）"],
    "不覆盖": ["中国 A 股：企业会计准则只要求分部收入/成本，无实物量口径"],
    "推论": "候选不在上述制度下 → 制度性不可得"
  },
  "不良贷款率": {
    "强制制度": ["银保监会《商业银行信息披露办法》"],
    "覆盖": ["A 股/港股上市银行全部"],
    "推论": "可得"
  }
}
```

规律可泛化到全部原型：

| 原型 | 关键口径 | 强制制度 | 可得性 |
|---|---|---|---|
| 耗竭资源型 | C1 / AISC | NI 43-101 / JORC | 仅该制度下可得 |
| 金融息差型 | 不良率、拨备、净息差 | 银保监强制 | 可得 |
| 金融承保型 | EV、NBV | 内含价值报告强制 | 可得 |
| 平台网络型 | 留存率、Rule of 40 | **无任何制度强制** | **永不可得**，只能估算 |

**缺条目时系统报「该口径尚未确定制度依据」，不静默退化成 PE/PB。**

## 六、组件 3：workflow 形状

新文件 `.claude/workflows/peer-comparability.mjs`。

```
盘点        已有台账？缓存命中？跨会话续跑跳过已完成的
    ↓
定品种      读标的主营描述 → 品种词 + 确认原型
    ↓
候选发现    并行多通道：A股 universe / 港股 / 跨市场联网（按披露制度定向找）
    ↓
三层判定    pipeline —— 每个候选独立走三层，一层不过即出局（fail-fast）
    ↓
口径可得性   对通过的集合，逐条必比口径判三态：可得 / 个案未披露 / 制度性不可得
    ↓
定向抽取     只对「可得口径 × 通过候选」派窄任务抽数，共用一张口径卡；偏离即出局
    ↓
出台账      算 N → 按 N 决定措辞 → 落盘
```

**四条要点：**

1. **三层判定用 `pipeline` 不用 `parallel`**——候选之间无依赖，不设 barrier，与 `equity-thesis.mjs` 的「一产出就核查」同源。
2. **fail-fast 省钱**：第一层淘汰的候选不进第二层，而第二层要读年报（最贵）。探针那 6 个候选里只有 1 个该走完全程。
3. **抽取共用一张口径卡，偏离即出局**——可比性靠事后验证「每家是否真用了同一把尺」保证，不靠事前定义。
4. **独立可跑**，不必依附判断稿。

## 七、组件 4：接口

### 被 `equity-thesis.mjs` 内联调用

Workflow 允许一层嵌套。`/thesis-wf`（顶层）→ `equity-thesis`（第一层）→ `peer-comparability`（子步骤）合法。

**但按名称解析有时机问题（2026-08-27 实测，见第八节）**：`.claude/workflows/` 的名称注册表在会话启动时加载，**当天新写的 workflow 在本会话里按名称解析不到**。所以内联调用要写成能降级的形式：

```js
// 名称优先（注册表已刷新时命中），失败则回退到 scriptPath——
// 新写的 workflow 在写它的那个会话里按名称必然解析不到。
let ledger
try {
  ledger = await workflow('peer-comparability', { variety, archetype: doubt.archetype, root: ROOT })
} catch (e) {
  ledger = await workflow(
    { scriptPath: `${ROOT}/.claude/workflows/peer-comparability.mjs` },
    { variety, archetype: doubt.archetype, root: ROOT }
  )
}
```

板块基准 agent 从「自己跑 discover_peers 两阶段」简化为「读台账」。`discover_peers.py` 降级为候选发现的通道之一。

### 产物路径（按品种，D4）

```
data/_peers/{品种}/ledger.md      可比性台账（跨标的复用）
data/_peers/{品种}/口径卡.md       本品种的取数口径定义
data/_peers/_regimes.json         口径 → 披露制度 缓存（全局）
```

### 喂进参照系五档（机械映射）

| 台账状态 | 参照系强度 |
|---|---|
| 可得 + N≥3 + 全部通过三层判定 | 外部·可回溯 |
| 可得 + N=1 或 2 | 外部但口径存疑（措辞带 N） |
| 个案未披露 | 外部但口径存疑 |
| 制度性不可得 | 无参照系 |

硬约束 7 因此自动生效：03858 的「板块 P/NAV」落到「无参照系」，开篇压在它上面必须降级措辞；「EV/资源吨 N=1」落到「外部但口径存疑」，可用但须标注限制。

### 原型表的两处小改

- 文件头写明 `归属判据` **有第二个用途**（反向判候选），否则后人不知道改它会影响什么；
- `必比口径` 每条可挂「制度依据」指针，指向 `_regimes.json`。

## 八、实跑验证（2026-08-27）

设计定稿后先写了一个最小但真实的 `peer-comparability.mjs`（按设计跑真 agent，范围锁在「钨」）验跑通。**三个发现全部是缺陷，不实跑不会知道。**

### ① workflow 名称注册表在会话启动时加载（设计缺陷）

`Workflow({name: 'peer-comparability'})` 报 `not found. Available: deep-research`——`.claude/workflows/` 下的脚本在**写它的那个会话里**按名称解析不到，必须用 `{scriptPath}`。

影响第七节的内联调用接口：直接写 `workflow('peer-comparability', ...)` 在新写当天会抛错。已改为「名称优先 + scriptPath 回退」的形式。

### ② `meta` 必须是纯字面量，而既有校验器验不出（工具缺陷）

`whenToUse` 里用了字符串拼接，`tools/check_workflow_syntax.mjs` **放行了**，运行时才报
`meta must be a pure literal: non-literal node type in meta: BinaryExpression`。

**一个会放行跑不起来的脚本的校验器，比没有校验器更糟**——它给出「已经验过」的错觉。这与本项目要消灭的失败形状同类：形式合规、实质无效、无信号。

已给校验器补 meta 纯字面量检查：剥掉注释与字符串字面量后，骨架里不得出现 `+`、模板串、展开运算符、函数调用。

### ③ 第一版补丁是坏的，反例照样放行（同一教训第三次）

补上的第一版正则太弱，拼接反例仍 EXIT=0。重写为「剥字符串后查骨架」才真抓到，并用两个反例（拼接、模板串）验证 EXIT=1。

**「只加不会失败的断言等于没加」在本项目群里已出现三次**：参照系接地的原型表结构断言、硬门的攻击测试、这里的 meta 检查。凡新增校验，必须用反例验证它真会失败——这条应视为本仓的通用工序，而非个案提醒。

## 八点五、外部框架校准：中金行业体系（2026-08-27）

设计定稿后翻了中金点睛的指标库分类树做横向校准。**它的切法比本设计多一层，而那一层正好是
本设计第二层判定最吃力的地方。**

### 它的树是五层

```
中金行业体系
  └ 基础材料              行业大类（12 类：能源/基础材料/工业/交通运输物流/公用事业/
     └ 有色金属            子行业   金融/不动产与空间服务/科技/医疗健康/可选消费/日常消费/汽车及出行设备）
        └ 钨               品种（铜/铝/锂/钴/镍/稀土/…/钨/…，末尾并列一个「个股数据」）
           └ 钨精矿 / 仲钨酸铵 / 钨铁 / 碳化钨 / 钨深加工 / 钨粉 / 钨条 / 钨酸钠 / 钨丝
                          ↑ **产业链环节** —— 本设计缺这一层
              └ 价格 / 表观消费量 / 周度开工率 / 进出口 / 产量 / 库存 / 成本 / 利润 / 产能
                          ↑ 固定 9 指标模板，在每个环节下原样重复
```

### 借鉴一：把第二层判定从推理改成查表

本设计的第二层（业务性质）靠「反向套用归属判据 + 读年报找会计痕迹」，每个候选要读几百页。
按产业链环节切之后，大部分情形变成**定位**：

- 03858 在「钨精矿」环节，翔鹭钨业在「钨粉/钨丝」环节 → **不同环节，不可比**，一句话结束
- 章源钨业**横跨精矿与钨粉两环**，自给率 15–17% 说的正是它在上游那一环的占比 → 这才需要深挖

**只有横跨多环节的候选才需要读年报**，读年报的成本因此降一个量级。

### 借鉴二：指标模板固定，不按节点定制

九个指标（价格/表观消费量/开工率/进出口/产量/库存/成本/利润/产能）在每个环节下一模一样地重复。
中金靠模板覆盖几千个节点，不是逐个手写。

对照本设计：`必比口径` 是**按原型**写的（15 套）。两者应当合并——
**原型决定估值口径（P/NAV、EV/资源吨），环节决定实物口径（产量/产能/库存/开工率/成本/价格）。**

### 借鉴三：指标命名法本身就是口径规范

```
冷轧板 : 考虑1个月原料库存 : 成本 : 当日值      ← 对象 : 口径限定 : 指标 : 统计形态
中国 : 汽油 : 产量 : 当月值
华虹半导体 : 营业收入 : 当季值
```

冒号分层里的**口径限定槽位**（「考虑1个月原料库存」）就是本设计说的口径卡——
它是让两个「成本」可比或不可比的那个东西。每条指标另带 `数据来源`
（中金钢铁&Mysteel / 卓创资讯 / 公司公告 / 国家统计局 / 官方网站）与 **`研究人员`**：
前者对应本设计的参照系五档，后者是问责。

### 边界

借鉴的是**结构**（多一层环节、模板化指标、口径写进命名），不是数据。
中金的指标数据是订阅内容且带水印，不进本仓。

## 九、验收标准

1. `peer-comparability` 能独立跑通，对「钨」产出台账，判定结果与探针一致：章源可比、厦钨/中钨部分可比、翔鹭不可比、江钨装备/厦钨新能品种层即出局。
2. 台账中「不可比」各行都有可回溯到年报的依据文字。
3. `N=1` 时产物中不出现「中位数」三字。
4. `_regimes.json` 至少含耗竭资源型的四条口径，且「C1 成本曲线分位」标为 A 股制度性不可得。
5. 由 `equity-thesis.mjs` 内联调用能拿到台账（一层嵌套不抛错）；**名称解析失败时 scriptPath 回退生效**。
6. 台账按品种落盘，第二次对同品种不同标的运行能命中缓存。
7. `tools/check_workflow_syntax.mjs` 对「meta 含拼接」「meta 含模板串」两个反例返回 1（防止第八节②③再次发生）。

## 十、已知边界

- **跨市场抽取依赖联网**。NI 43-101 技术报告在 SEDAR+ 上公开但需检索；本设计只保证「制度层判定告诉你去哪找」，不保证一定抓得到。
- **平台网络型等原型的关键口径无制度强制**，永远只能估算——系统的正确行为是判「制度性不可得」并降级，不是硬凑。
- **归属判据反向套用未在全部 15 原型上验证**，仅在耗竭资源型上有探针证据。首次跑到新原型时应人工复核该层判定。
- **本设计不解决 03858 的估值对比**。纯钨矿上市公司全球稀少，P/NAV 样本可能永远 N<3。能解决的是：给出真实可得的坐标（EV/资源吨）+ 诚实的 N + 明确的「哪条口径为什么拿不到」。
