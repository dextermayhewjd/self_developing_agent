# 参照系接地（Benchmark Grounding）设计

日期：2026-08-26
状态：设计已确认，待写实施计划
触发：基金经理反馈 03858 判断稿「缺少板块特定性」

---

## 一、问题陈述

### 表象

`reports/03858_thesis_20260821/report.md` 是一份矿业语言过关的稿子——品位、边界品位、
选矿回收率反推、LOM 与采矿权期限比对、储量转化期权都做了，甚至推翻了 `framework.md`
给周期股开的「穿越周期 P/B」处方，自己改用矿山 NAV。

但它的核心结论是：

> 286.3 亿港元市值 = 独立技术报告税后 NPV 的 2.31–3.25 倍，所以贵。

**这句话无法区分板块 beta 与个股 alpha。** 如果同板块在产钨矿普遍在 3x NAV 交易，
它说的是「钨板块贵」，不是「佳鑫贵」，基金经理拿它没法选股。而那个板块中位数，
全文从头到尾没有出现过。

### 根因

**根因一：框架的样本全是成长股。** `framework.md` 开篇写明来源是石基/乐鑫/中控/开立/澜起
五份底稿——软件、芯片、工业软件、医疗器械、IC 设计，没有一个资源股。着墨对比：

| | 行数 |
|---|---|
| 成长股 | `framework.md` 493 行 + 5 个 lens 文件 |
| 周期股/有色 | 4 行（`framework.md:40`、`framework.md:322`、`产业.md:123`、`financial-redflags-cn:70`） |

**根因二：同业池按交易所行业分类抓，不按品种。** `fetch_hk_peers.py` 的设计是「一次请求
拿回全行业」，省掉手工维护，代价是拿回港股「一般金属及矿石」72 家，里面一家钨矿都没有。
A 股的 `competitor_pool.json` 是手工池，只有 10 个行业，同样没有有色。

**根因三：五个 lens 的分工是成长股的分工。** 资源股真正的重活「商品价格与成本曲线」
被摊在产业和竞争两个 lens 里，两边各做一半，谁也不负责成本曲线分位和供需平衡表。

### 系统已经诊断过三次，零次修复

| 位置 | 内容 |
|---|---|
| `lenses/核查.md:68-76` | 「03858 五条承重数字全部核实通过，但没有一条是外部同口径……核查全部通过，判断照样悬空」 |
| `equity-thesis.mjs` `FINDINGS` schema 注释 | 「五条承重数字全部回原文核实通过，但没有一条比过外部同口径」 |
| `report.md` 第七节 | 「这是本篇最大的调研缺口，我在第十一节因此完全不用相对估值法」 |

三处都停在「记录问题」。**这比缺口本身更值得处理——诊断能力已经具备，缺的是把诊断
接成动作的控制流。**

### 为什么现有机制拦不住

`FINDINGS` schema 早就有 `benchmark` 字段，要求每个承重数字填参照系。03858 五条**全部
填了**，但没有一条是外部同口径。结论：**lens agent 一边读几百页年报一边兼职查同业，
必然敷衍。参照系不能挂在挖掘 agent 身上，必须是独立职责。**

## 二、设计约束（由使用者给定）

1. **手工维护的内容只写行业标注，且一旦手工维护就必须全面。** 不接受「补一段资源股、
   其余每类一行」这种半成品。
2. **数据层的行业池必须动态检索。** 细分品种的分类方式无法人工穷尽，不接受扩充手工名单。
3. **「私有基准/无参照系」要系统性解决，不是打补丁。**

## 三、关键决策

| # | 决策 | 取舍 |
|---|---|---|
| D1 | 行业标注按**估值原型**切，12–15 类，不按行业名 | 按行业名切要么太粗（「有色金属」一段管不了铜/金/钨），要么太细（申万三级 346 类写不完也维护不动）。按「现金流形态」切才是真正可穷尽的维度 |
| D2 | **定向放行联网**给参照系 agent | 现有全线禁网有两个理由：核查要「回原文」、成稿要防越权烧预算。参照系 agent 两条都不沾——它查的是外部可比公司，按定义就不可能出现在标的年报里 |
| D3 | 参照系接地**拆两半**（板块基准并行 + 补参照系收口） | 板块级基准只依赖原型与同业名单，立疑后即可开查，可完全藏在五个 lens 的墙钟里；个股级参照系才需等核查 |
| D4 | 硬门**只拦开篇结论** | 全面拦会让资源股/次新股每篇都被拦，写稿的人学会批量粘声明句，硬门失去意义。悬空在正文里是诚实，悬空在开篇第一句而不声明才是误导——而基金经理只读开篇 |

**新文件** `.claude/skills/equity-thesis-cn/valuation_archetypes.md`。
`framework.md` 原则三那张 8 行表改为指向它。

### 每段的固定字段

标注不是散文，是**机器可消费的契约**——组件 3 直接读 `必比口径` 派活。

```
## 1. 耗竭资源型

归属判据：主要资产有可枯竭的储量，产出为同质大宗商品，售价外生
主估值方法：P/NAV（以储量/资源 NPV 为基座）
失效指标：
  - 当期 PE（分母全看商品价假设，同一天可差 10 倍）
  - PB（矿按历史成本入账，分母是募来的钱不是矿的价值）
必比口径：                          ← 组件 3 读这一段派活
  - 板块 P/NAV 中位数（在产 / 开发中分开取）
  - EV / 资源吨（含金属量口径）
  - EV / 单位年产能
  - C1 或 AISC 在全球成本曲线的分位
必做分析：供需平衡表、政策配额、再生供给响应、储量寿命 vs 采矿权期限
排雷阈值变体：折耗政策、剥采比资本化、复垦拨备、投产爬坡期净现比可为负
典型悬空点：成本曲线位置与储量 NPV 往往只有公司委托的技术报告一个来源
```

`必比口径` 是这张表存在的理由：它把「这一节该跟什么比」从模型的自由发挥变成配置。

**工作量**：15 段 × 约 250 字 ≈ 4000 字，一次写完。之后只在原型定义本身变化时才动，
远慢于行业分类的漂移速度——这是它能满足约束 1 的原因：**它全面得起，因为本来只有 15 项。**

## 五、组件 2：动态同业检索

**新文件** `tools/discover_peers.py`。`competitor_pool.json` **不再扩充**
（它违反约束 2，且只有 10 个行业、A 股专用）。

### 核心思路

不去猜「钨矿属于哪个分类」，而是先问「这家公司到底卖什么」，再拿品种词去检索。
品种词天然动态、天然准确，不需要任何人维护分类体系。

```
L1 品种提取
   从 aggregate.json 主营描述 + findings/尽调.md 提取品种词
   例：03858 → 「钨精矿」「65% WO3」；澜起 → 「内存接口芯片」「DDR5 RCD」

L2 候选检索（多通道，降级不塌，通道顺序见第八节）
L3 LLM 确认
   逐个候选读主营描述，判「同品种否 / 口径可比否」
   输出：保留 + 一句理由，或剔除 + 一句理由

产物 data/{SYMBOL}/peers_curated.json
   { 生成日期, 品种词, 通道, peers:[{code, market, keep, reason, manual}] }
```

### 三条设计约束

**幂等**：已有 `peers_curated.json` 且未过期就跳过，与 `validate.py` 现有风格一致。

**人工可覆盖但不可替代**：人写的条目标 `manual: true`，重跑不覆盖。这是唯一保留的
人工入口——**人只做「加一家机器没找到的」，不做「维护一整张分类表」。**

**保留现有宽池子**：`peers.json`（72 家一般金属及矿石）不删。新体系里两者分工明确：
`peers_curated.json` 给「同品种可比」，`peers.json` 给「板块整体在什么估值水平」。
**03858 那篇同时需要这两个数才能回答「是板块 beta 还是个股 alpha」。**

## 六、组件 3：参照系接地（workflow 控制流）

改 `.claude/workflows/equity-thesis.mjs`，新增两个 agent。

```
盘点 → 立疑（输出 archetype）
         ├─→ 板块基准 agent ──────────────┐  与五 lens 同槽并行，零额外墙钟
         │    读原型的「必比口径」→          │
         │    discover_peers → 算中位数     │
         │    → 参照系/板块基准.md          │
         └─→ pipeline(五 lens: 挖掘 → 核查)─┘
                          ↓
              补参照系 agent（只对仍悬空的承重数，一条没有就整段跳过）
                          ↓
                    成稿 → check_thesis 硬门
```

### 3a. 板块基准 agent

**输入**：立疑判定的 `archetype`。
**动作**：读 `valuation_archetypes.md` 该原型的 `必比口径` → 跑 `discover_peers.py`
→ 逐条算板块中位数/分位。
**产物**：`参照系/板块基准.md`。

**接口改动**：立疑当前输出 `industry_class`（自然语言），`疑惑.md` 第一行是
`行业类别：<判定>`，五个 lens 都从这读。改为 **`估值原型：<15 选 1>`**——原型表同时承载
估值方法、必比口径和排雷阈值变体，一个分类喂三处，比自然语言字符串可靠。

### 3b. 补参照系 agent

**触发**：扫所有 `核查/*.md`，取出判定为「私有基准」或「无参照系」的承重数字。
**一条都没有就整段跳过**——这是拆两半消掉 barrier 代价的地方。

**这是唯一放行联网的 agent。** 护栏必须是结构性的而非 prose——`debug-equity-thesis:92`
已记录教训：编排器越权 round1=257 次，加 prose 禁令后反升到 299 次，**prose 禁令无效**。

| 护栏 | 实现 |
|---|---|
| 联网所得必须留痕 | 写进 schema：每条外部数必须带 `url` + `verbatim`（逐字原文）+ `fetched_date`，缺任一字段 schema 校验直接打回 |
| 只查别人不查自己 | 扩展 `tools/audit_overreach.py`，加判据：转录中是否出现「标的代码/公司名 + 财务字段」的检索 |
| 外部数不许自动升最高档 | 见下方强度分级，「可回溯」需 ≥2 源交叉或来自本地数据层 |

**产物**：`参照系/补.md`。

### 强度分级：四档改五档

`lenses/核查.md` 当前四档。联网放行后「外部同口径」会从「本地算出来的」变成「搜来的」，
两者可核实性差一个量级，必须拆开：

| 档 | 定义 | 能否当硬数字 |
|---|---|---|
| **外部·可回溯** | 有 URL/接口 + 逐字原文 + 口径说明，且 ≥2 源交叉，或直接来自本地数据层 | ✅ |
| **外部·单源未交叉** | 有出处但只有一个来源 | ⚠️ 正文须标注 |
| **外部但口径存疑** | 有外部数但口径不一致 | ⚠️ 正文须标注 |
| **私有基准** | 出自标的公司或其委托方 | ❌ 结论必须降级 |
| **无参照系** | 没有可比对象 | ❌ 结论必须降级 |

本地数据层直接进最高档——`discover_peers.py` 从 akshare 算出的中位数天然可复现，
比搜来的两个源还硬。

### 反向检查：宽池子倍数不许伪装成同业对比

**这条是 03858 一个实质错误的直接防线（见第九节）。**

若某个板块倍数来自**宽池子**（如港股「一般金属及矿石」72 家）而**池内无同品种**，
一律判为「**外部但口径存疑**」，并且：

- 不得用于开篇结论（由第七节硬门执行）
- 正文引用时必须写明池内无同品种，且不得据此计算「是中值的 N 倍」这类倍数

理由：**错误的参照系比没有参照系更危险。** 缺参照系会被判为「无参照系」从而触发降级；
而一个形式上是外部数、实则不可比的池子，不会触发任何警报——它看起来完全合规，
报告还会煞有介事地拿它算倍数。03858 那次算出的偏离度因此错了一个数量级。

### 成稿 agent 的输入变化

从「读 findings/ + 核查/」改为「读 findings/ + 核查/ + **参照系/**」，
`数字纪律` 三行表改为按五档分档。

## 七、组件 4：check_thesis 硬门

### 可机检的前提

散文里做数值字符串匹配太脆。做法是**在开篇结论下方跟一个结构化声明块**，不污染散文：

```markdown
## 〇、开篇结论

<散文，核心两点，写法不变>

> **参照系声明**
> 核心第一点压在「市值 / ITR 税后 NPV = 2.31–3.25 倍」——参照系类型 **私有基准**
> （ITR 由公司委托 SRK 出具）；板块 P/NAV 中位数**未取得**（境外可比公司不可得）。
> 故本判断在绝对口径下成立，**相对板块的贵贱本篇无法回答**。
> 核心第二点压在「2029 年给矿品位 0.228%→0.140%」——参照系类型 **私有基准**（同一份 ITR）。
```

### 检查逻辑

```
若 参照系/ 不存在 → 跳过本项 + warn（向后兼容旧 run）

1. 解析 参照系/*.md → 建立 {数字描述 → 强度} 映射
2. 定位 report.md 的〈〇、开篇结论〉→ 必须存在 `> **参照系声明**` 块
3. 声明块必须逐条点名核心两点各压在哪个数上，
   且每个被点名的数必须能在映射里匹配到          ← 防模板化空泛声明
   **匹配以 `what` 字段为键**：`VERIFIED`/`FINDINGS` schema 里每个承重数字本就带
   `what`（该数的文字描述），参照系文件按 `what` 落盘。声明块必须原样引用 `what`
   串，check_thesis 做精确串匹配。不做数值模糊匹配——数值会被改写、四舍五入、
   换单位，`what` 不会。
4. 若某数强度 ∈ {私有基准, 无参照系}
     且 声明块缺降级措辞（「无法回答」「未取得」「绝对口径下」一组关键词）
   → exit 1，不得交付
5. 其余节的观点总结出现同类情形 → exit 2 软警告
```

第 3 步是防绕过的关键：**声明必须点名具体数字，而那个数字必须在参照系清单里匹配得上。**
泛泛一句「本报告部分数据未经外部验证」匹配不上任何条目，照样 exit 1。

### 顺带改动

**盘点 phase** 加 `参照系/` 的盘点，否则跨会话续跑会重跑板块基准（`3b8d6e8` 加盘点即为此）。

**`equity-thesis-cn/SKILL.md`** 步骤 3.5 后插入新步骤，「数字纪律」三行表改五档表——
这是给自然语言路径用的；workflow 路径由脚本保证。

```
通道③ 概念/行业板块   stock_board_*_em（push2）      ✗ 当前不可用，降为备选
同业估值口径          stock_value_em                 ✓ 已实测可用
—— 联网通道（仅补本地拿不到的）——
通道④ 跨境同业/成本曲线分位/商品价格序列   仅参照系 agent，受 D2 护栏约束
```

**本地优先是硬规矩，不是偏好**：凡本地通道能取到的数，一律不许走通道④。

理由是实测出来的（见第九节）：A 股四家钨业公司的估值本地当场可得、可复现、
带交易日；而同一类数搜来的往往出自有立场的研究文章，且交叉验证经常失败。
**本地数据的可核实性天然高一档**，这也是第六节把「来自本地数据层」直接判为
「外部·可回溯」最高档的原因。不写死这条，agent 会图省事全去搜。

多通道降级设计正好接住了 push2 这件事——**组件 2 不需要重写，只是把通道顺序倒过来。
组件 1、3、4 不受影响。**

## 九、实测验证（2026-08-26）

设计确认后做了一轮端到端可行性实测，三条结论都改变了方案的细节。

### 验证一：联网确实能拿到缺失的锚 —— D2 成立

一次 WebSearch 即命中 **Almonty Industries（NASDAQ: ALM，韩国 Sangdong 钨矿）
P/NAV 0.19x**，另有 American Tungsten EV/NAV 0.3–0.5x，以及矿业板块 P/NAV 常规区间
0.5–1.5x、优质金矿 0.75–0.90x。

对照 03858 的 2.31–3.25x —— 这正是报告里那句「贵」始终悬空的参照系。
**D2 的联网放行不是空头支票。**

### 验证二：A 股同业本地即可得，且暴露了报告的一个实质错误

`stock_value_em` 当场取到四家钨业公司 2026-08-25 数据，无需联网：

| | 总市值(亿元) | PE(TTM) | PB |
|---|---:|---:|---:|
| 厦门钨业 600549 | 831.7 | 23.49 | 4.45 |
| 中钨高新 000657 | 1454.0 | 51.72 | 12.89 |
| 章源钨业 002378 | 299.8 | 34.74 | 10.39 |
| 翔鹭钨业 002842 | 122.4 | 31.72 | 8.38 |
| **中位数** | | **33.23** | **9.39** |

03858 为 PE 93.8 / PB 17.86。用真正的钨业同业比：**PE 是中位数的 2.82 倍，
PB 是 1.90 倍。**

而 `report.md` 第七节写的是——用港股「一般金属及矿石」72 家的中值 PE 5.69 / PB 0.79
——**「16.5x 中值、22.6x 中值」**。

**错了一个数量级。** 依然贵，但「贵 2.8 倍」与「贵 16.5 倍」是两个不同性质的判断。
这催生了第六节的「反向检查」，并把本地优先写成硬规矩。

### 验证三：交叉验证会真的失败 —— 「≥2 源交叉」护栏必要且有效

用第二个角度去核 Almonty 的 0.19x，**没核上**；第二轮搜索反而返回方向相反的说法
（"leans expensive on market multiples"）。该数很可能出自有立场的多头文章。

按第六节分级，0.19x 只能进「**外部·单源未交叉**」，正文须标注、不得据以直接下结论。
**如果没有这条护栏，agent 会把一篇多头软文里的数当成板块基准——那比现在的悬空更糟。**

## 十二、已知边界

- **跨境同业依赖联网。** Almonty（NASDAQ: ALM）、Masan（越南）只能靠通道④。第九节已
  验证联网确实取得到，但**取到的数往往只能进「外部·单源未交叉」**——交叉验证失败是
  常态而非例外。联网若被禁、失败、或只拿到单源，03858 这类标的仍会停在不可用作硬数字
  的档位，此时系统的正确行为是**降级结论并硬门拦截**，而不是假装比过了。
  这是 D4 存在的理由，也是为什么本方案的骨架是「结论强度锁死于参照系强度」而非「消灭悬空」。
- **月度商品价格序列的替代方案**未定。当前设计下，缺它会让耗竭资源型的「必做分析：
  供需平衡表」永远只能部分完成，对应结论按五档降级处理——即系统行为是确定的，
  但信息量的上限受此限制。
