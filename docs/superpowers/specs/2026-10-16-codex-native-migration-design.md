# Codex 原生研究工作流迁移

## 用户目标与已确定边界

用户要求把本仓库 `.claude` 的运行方式完整迁到 `.codex`，并明确选择保留确定性编排器、全部阶段由 Codex 执行。迁移完成的含义是本仓库不提供 `.claude` 目录时，Codex 仍能发现、运行、审计这些能力；不宣称 Codex 内置了 Claude 的 Workflow API，也不宣称不同模型的研究质量相同。

本次在已有 `sda-dev` 独立工作树实施，保留 Claude 版本、既有报告及用户未提交改动。迁移源包含当前未提交的研究方法更新。不启动新的真实股票研究，不改写已有报告。

## 架构

- `.codex/skills/` 是六个 Codex 技能及配套资料的唯一正文来源：`thesis-wf`、`equity-thesis-cn`、`equity-report-cn`、`financial-redflags-cn`、`calibrate-equity-thesis`、`debug-equity-thesis`。
- `.agents/skills/<name>` 使用相对目录链接指向 `.codex/skills/<name>`，接入 Codex 官方发现机制；不是维护第二份正文。
- `.codex/workflows/` 存三个独立 Codex 工作流定义，调用现有 Node 编排器及 `codex exec`。所有运行路径、指纹、档案提示改用原生资源，不回退读取 `.claude`。
- 方法文件保持完整，平台专属说明翻译为 Codex 工具；旧散文编排与脚本冲突的部分拆出，成稿只读写作契约，不再加载旧调度指令。
- 共享 Python 数据工具仍位于 `tools/`；同业池使用显式原生配置或平台中立资料，避免准备数据时隐式回到 `.claude`。
- Codex 审计读取 `.codex-workflow/events.jsonl` 和 `agents/*/events-*.jsonl`，报告阶段、失败、读取/写入/检索行为及可确认的越界信号。启发式不冒充证明。

## 完整校准

保留五份盲抽、独立归纳、独立规则测绘、对撞、抽查、诊断与改写稿全链。五份证据和方法全部齐备才复用盲抽与归纳；不齐时全组重建。盲阶段使用中性工作目录，归纳只获得内联 JSON；运行输出按日期隔离，原始 PDF 可配置。

对撞需要十二节乘五篇矩阵、适用域分母与支持度。新增提案要求至少三份适用底稿支持；删除提案要求零命中且至少三份适用底稿。分母为零不可提案。所有修改提案经原文抽查后输出 before/after 草稿，绝不自动修改研究方法。保留样本仅五份及无法证明运行改善这两个限制。

## 恢复与权限

沿用现有进程锁、事务恢复、模型配置冻结、结构化结果、独立成稿审查和 PDF 顺序。迁移改变输入指纹，旧运行明确要求 `--reset`，不自动改状态或归档用户产物。遵循 Codex 当前权限，不复制 Claude 的 bypassPermissions。

## 验收

1. 六个技能清单可由本机 `skills/list` 发现，链接无断裂；所有本地引用可解析。
2. 不含 `.claude` 的隔离副本中，三个工作流通过无模型控制流检查；合成后端验证真正的文件交接和校准全链。
3. Codex 日志审计覆盖完成、失败、不完整与越界信号，不能把日志缺失认定为通过。
4. 原生资源指纹覆盖方法与工作流修改；保留已有恢复、审查与交付回归。
5. Node 和 Python 项目回归通过，独立技能行为检查通过。真实模型探针若执行，只用临时合成资料，不生成股票报告。

## 非目标

不迁移仓库外的 Claude 生产 wrapper、OpenClaw 调度或全局设置；本仓库没有 Claude hooks/MCP/settings 需转移。不为页数而扩写报告，不把路径迁移称为研究质量验证。
