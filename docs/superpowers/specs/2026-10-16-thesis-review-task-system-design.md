# 判断稿审查任务系统与轻量 subagent 执行

日期：2026-10-16。状态：实施及最终独立复查完成；最终Node326/326，真实Codex CLI合成传输链路通过。

## 1. 用户目标与本批范围

用户已选择保留确定性 Node 编排器，研究阶段由原生 Codex 执行。本次要求使用 Superpowers，将审查发现的问题转成可追踪任务，给轻量 subagent 提供清楚、必要的上下文，再完成修订和独立复核。

本批实现单张改动图中的审查任务清单、定向修订、复核、相关版本恢复，以及支持它们所必需的图片证据合同。入口仍为现有 `$thesis-wf` 和 CLI，运行资源位于 `.codex`。业务识别、同业范围、成稿前写作规划属于另一批研究流程改动，不与本批混合归因。

成功标准：已发现的问题不丢失；局部问题能交给小上下文 worker；任务作者不能自行关闭任务；跨节问题交回统一修订者；中断恢复不会重置修订额度；未通过的候选稿不授权档案/PDF 交付。

实现继续使用当前已隔离的 `sda-dev` linked worktree，不创建另一份工作树，不处理其他未提交修改。

## 2. 方案选择

采用“文件持久化任务清单 + 现有 runtime.agent 调度 + host 校验补丁”的方案。运行内任务管理即可满足需求，不增加服务或数据库。

不采用 worker 并发直接编辑 `report.md`：这会造成覆盖、过期上下文和难以追溯的修改。不把完整报告及全部底稿重复发给每个轻量 worker；独立完整审查和统一修订者保留全量上下文。

“轻量”在首版指：必要上下文、局部职责、默认 low 推理强度。模型沿用冻结配置，允许按新阶段覆盖，不硬编码一个未经当前模型目录验证的型号。独立审查不因本功能而自动降级。

## 3. 执行顺序与职责

1. 原有五路研究、核查、参照系和成稿产出候选报告。
2. 独立审查完整阅读报告、全部当前底稿和证据附件，返回覆盖判断及结构化问题。
3. host 验证审查与证据、分配稳定任务 ID，原子保存清单。审查通过且无未解决阻断任务时进入交付验证。
4. 对尚未解决的问题分流：局部补写由轻量 worker 提案；估值/评分/承重假设或大范围联动交统一修订者；缺证据任务记录缺口，禁止编造材料。
5. worker 仅返回补丁提案。host 校验基础版本、目标范围和原文唯一命中后应用，保存新候选版本，任务进入待复核。
6. 独立审查重新读取改后全文与全部底稿，对每个旧任务给出处置，并允许追加新重大问题。只有当前版本的独立复核可以关闭任务。
7. 持续存在阻断任务且额度耗尽时保存检查点并停止。通过后仍须引用/版本验证、档案与硬门检查，最后才生成 PDF。

全文独立审查保留，任务清单不成为限制审查发现范围的名单。

## 4. 持久文件与所有者

所有控制材料放在 `RUN/.codex-workflow/review/`，不放进自动递归读取的 findings/核查/参照系目录，避免自引用。

```text
review/
  ledger.json                   # 当前已提交任务状态的兼容入口
  HEAD.json                     # 最近完整 commit 的引用
  commits/CP-000001.json         # 不可变提交记录与前序关联
  ledgers/LG-000001.json         # 不可变任务状态版本
  evidence-manifest.json        # 来源类型、原始字节 SHA、转录关联
  reviews/RV-000001.json         # 不可变审查结果
  receipts/RV-000001.json        # 审查输入与 host 入账结果的绑定
  reports/RP-000000.md           # 不可变报告版本
  contexts/RT-000001/A-0001.json # 实际交给 worker 的上下文包
  proposals/RT-000001/A-0001.json
  attempts/A-0001.json           # 轮次、输入/输出摘要与任务 ID
```

`report.md` 保留为当前候选的兼容入口；`成稿审查.json` 保留为最新审查入口。历史文件不覆盖。host 是 ledger 与候选报告的唯一应用者；审查员返回判断，修订 worker 返回提案。任务真相以 HEAD 引用的完整 commit 中的 ledger 为准，不能把半写入的兼容文件当作已提交状态。

ledger 不依赖 `stage.status=succeeded` 判断完成。该状态只说明一次模型调用成功，不能表示审查通过或任务已关闭。

## 5. 任务合同与状态

每项至少记录：

- `id`：host 单调分配 `RT-000001`，运行内稳定，不由描述文字或报告哈希生成。
- `kind`：`blocking`、`disclosure`、`watch`。
- `blocks_delivery`：blocking 固定为 true，watch 固定为 false；disclosure 的验收对象是必须写清的限制，未满足该要求时为 true，不要求查明底层未知事实。
- `status`：`open`、`awaiting_review`、`resolved`。
- `description`、`locations`、`evidence_refs`、`acceptance_criteria`。
- `route`：`local_patch`、`full_revision`、`needs_evidence`。
- 创建审查 ID、最近有效处置所绑定的报告/证据摘要及追加历史。

状态流转：

```text
open --host 应用有效修订--> awaiting_review
awaiting_review --独立复核确认--> resolved
awaiting_review --复核未通过--> open
resolved --独立审查发现复发--> open
```

writer/worker 的自评不能关闭任务。`watch` 可以保持 open 而不阻断；需要披露的限制须满足披露验收条件，可以通过准确写明未知和判断边界来关闭，不代表未知事实已查明。最终放行检查所有 blocks_delivery=true 的任务。任务不得为了放行而静默降级，变更类别或阻断属性需要独立审查记录理由。

每次后续审查必须唯一、完整地处置所有旧 ID；允许新增问题。拒绝未知 ID、重复处置、遗漏旧任务或无记录删除。首次审查中的多个表述可明确关联同一问题，避免章节、coverage、blocking 字符串重复建单。

`blocking_issues` 如保留用于显示，必须由结构化未解决阻断任务派生，不维护第二份自由文字真相源。

## 6. 轻量 worker 的上下文与输出

上下文包内联以下材料，路径用于回溯：

- 任务 ID、问题说明、验收条件、允许修改的章节。
- 基础报告 SHA 与证据快照 SHA。
- 目标章节完整原文，以及必要的邻接段落。
- 被引用证据的完整相关段落，包含单位、期间、正负号、核查状态和口径限制。
- 与该问题相关的报告判断约束原文；不由 host 新编财务摘要。

首版局部包上限为 UTF-8 32 KiB、最多两个目标章节；不通过静默截断满足上限。包含第十一节估值或第十二节评分，或需要改动主要估值锚、承重假设、概率与市值区间时，交统一修订者。范围不明确、证据冲突、上下文不足或超过上限也应升级。

worker 输出包含：

```text
task_ids, base_report_sha256,
status = proposed | needs_evidence | escalate,
edits[] = { section, before, after, rationale, task_ids },
evidence_refs, acceptance_checks, escalation_reason
```

worker 不直接写报告、底稿或 ledger，不自行增加数据、不联网补研究，不宣称任务已关闭。`needs_evidence` 和 `escalate` 是合法业务结果，不作为模型调用异常中止其他任务。

默认 low 推理强度，沿用当前模型和提供者；支持阶段配置 `问题修订`，动态任务标签归一到该阶段。保持现有 CLI 覆盖优先级，并记录最终实际配置。最终独立审查使用原审查阶段配置。

worker 使用专用提案指令，不能继承当前“写出全文”的通用阶段指令。中性工作目录、禁用项目技能/额外项目上下文、关闭 web_search、禁止递归派发。使用本机 CLI 已支持的 read-only sandbox，移除会选择 workspace-write 的 `--approve-for-me`，以 `--ask-for-approval never` 禁止提权请求。CLI 自身保存结构化输出的路径由 host 指定。

只读沙盒不等于文件读取 ACL；禁用 web_search 也不等于所有网络能力已被独立证明隔离。实际参数须通过后端测试与合成探针确认；环境无法提供该执行模式时报告失败，不回退扩大权限。

## 7. 提案应用、并发与升级

首版按任务顺序派发、校验与应用，避免同一报告基础版本上的重叠编辑。复用现有有界 runtime，不增加一套调度器。

host 应用前验证：任务仍有效、报告与证据版本未变、before 非空且在指定章节中唯一出现、各编辑不重叠、没有越出允许章节、提案包含完整验收响应。任何过期版本、重复锚或越界编辑都不写入当前报告，保留提案并重新安排或升级。

多文件提交顺序固定：先写报告/ledger/receipt 等不可变对象并核对摘要，再写包含所有引用及前序 commit 的不可变提交记录，最后原子更新 HEAD；兼容入口随后按已提交对象更新。HEAD 更新前崩溃只留下未提交对象；更新后崩溃则按最新完整 commit 恢复入口。恢复必须验证引用对象与摘要全部存在，不采用半提交结果。兼容入口若既不匹配前序版本也不匹配已提交新版本，按可能的人工编辑保留文件并报告冲突，不覆盖。

补丁校验只验证机械一致性；语义、重要性与财务判断仍由独立完整审查负责。worker 自评的 acceptance_checks 只是说明，不授权关闭。

需统一修订的任务可使用现有完整修订者处理一组关联问题，继续返回提案，仍由 host 应用和独立复核。证据确实不足时，修订者可以提出保留限制或降低结论强度的方案，由独立审查判断是否满足验收，不将缺证据自动标为已查明。

## 8. 审查和证据合同

审查请求和原始结果绑定 `report_sha256`、完整来源清单的字节摘要和输入 ledger 版本。host 验证新任务与处置后生成新的 ledger 版本，并写不可变 receipt，关联 review ID、输入 ledger SHA、输出 ledger SHA、报告和证据 SHA。最终检查 receipt 的输出 ledger 是否等于当前 ledger；不用审查输入哈希去匹配入账后的文件，避免自引用与关闭任务使自身审查失效。

receipt 之外再改变报告、证据或任务状态，都使旧 pass 失去交付授权。不得修改已归档审查来补写新 SHA。

文本来源保持全文读取和逐字引文校验。PNG/PDF 等二进制仅按原始字节计算摘要，不能按 UTF-8 验引文。图片引文使用关联原图路径、原图 SHA 与核验方式的文字转录；若原图来自 PDF，再记录 PDF 原件摘要、PDF 页序与印刷页码对应。保留原图和转录双方，不对无 PDF 来源的图片编造页码。

缺转录的图片先生成未核验的文本候选；OCR 或模型提取都不自动变成已核事实。完整审查同时获得原图与候选转录，独立逐字核对的结果引用双方 SHA 并归档在审查中。证据快照摘要包含物理来源与关联，不把审查处置状态混入来源字节摘要。没有有效目视核对记录的转录不能当作已核图片引文。

机器校验证明引用链和版本一致，不宣称证明 OCR 或财务推理正确。未支持或未核对的证据返回明确类型/核验缺口，不能跳过附件，也不能误报真实图片引文为伪造。

## 9. 轮次、恢复与失败状态

默认最多两轮修订，对应最多三次有效完整审查；绝对修订上限为 N 时，对应最多 N+1 次有效完整审查。修订轮次包含本轮的局部 worker 或统一修订，不按任务个数增加额度。改变 report.md 的交付修复也使用同一修订额度；纯 PDF 转换重试不消耗该额度。传输或结构化输出校验失败的重试保留调用日志，但不算一次有效语义审查，也不另开修订轮。

修订开始前持久预留 attempt，并保存固定任务集合、任务顺序、逐任务结果与当前报告版本。批次状态为 collecting/applying/finalized/reviewing：首版顺序执行，恢复时继续尚未完成的任务，不把只应用首项的半个批次送去复审；已完成应用不可重复执行。只有批次 finalized 后才启动对应完整审查。若没有可安全执行的修订且需要新证据，保存 needs_evidence 检查点，不用重复完整审查消耗额度。

预算、未关闭任务、基础版本、终止原因独立持久化，不能因重启或 review_only 清零。可增加绝对上限选项 `--review-max-rounds N`：新运行默认 2，恢复时默认沿用原值；显式增加才扩展预算并留日志，相同数值重复调用不重复授予额度。N 为正整数，上限 10，不允许小于已消耗轮数。

修复本轮已复现的原始输入/派生文件混合指纹问题：原始数据有显式清单；已知阶段生成的同业计算、benchmark_peers、check_sources 等登记为派生产物，不进入原始输入签名。新增未分类数据不能静默忽略。方法与原始文件内容变动仍需识别、拒绝错误复用或执行明确迁移。

旧 v1 状态不具备来源快照和任务 ID，不能自动视为已通过或修订零次。保留原文件，提供只读迁移诊断；自动迁移仅限可证明输入未变、轮次可恢复的情况。无法证明时明确列出缺口，禁止悄悄改 fingerprint 或重置预算。本批不自动改写先前300209报告与档案。
