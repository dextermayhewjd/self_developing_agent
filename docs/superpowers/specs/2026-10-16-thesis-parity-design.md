# Thesis 执行配置与成稿审查

用户已要求补齐上一轮建议的第 1、2 项。本次修改现有执行器与共享 thesis 流程，保留研究分工、数据权限及已有报告；不自动重跑真实股票，不开展双端模型评测。

## 执行配置

启动真实执行前，读取 Codex 有效配置和模型目录，解析具体模型与推理强度。显式 CLI 覆盖优先，其次阶段配置，其次有效默认；共享脚本的 Claude 模型别名不能直接传给 Codex。所有 worker 显式传模型与强度。支持阶段配置文件，以准确标签覆盖角色。记录配置来源、Codex 版本和阶段最终配置，不保存鉴权或完整用户配置。

将解析后的配置放入运行指纹、状态和每个 worker 的元数据。续跑从原状态恢复已锁定配置；显式变更要求 reset。无法解析模型/强度时明确失败，不默默猜测。无模型 --check 不连接模型，不创建业务产物。保留当前自动审批和网络边界。

## 独立内容审查

在共享 equity-thesis workflow 中加入成稿后的独立审查；两个后端执行同一阶段。审查读取完整 findings、核查、参照系、疑惑、写作指南与报告。输出独立 JSON 文件及结构化返回，包含十二节检查、五个 lens 的关键发现覆盖、遗漏/矛盾/保留/有理由排除、引用原文及具体修订要求。字数和页数不作为合格标准。

不合格时最多两轮仅利用现有证据的修订，再由独立 worker 复审；缺外部证据必须保留限制，不能编造或悄悄扩展为重采集。仍不合格阻止档案与 PDF 交付。增加 review-only 调用分支，供旧报告、硬门修复后的报告再次审查。结构检查或硬门修复不能使旧审查结果继续授权新版本报告。

Codex 交付侧确定性验证审查的十二节/五方向覆盖、状态和证据引用，并核对审查绑定的报告摘要；审查不完整、假引用、旧版本审查均阻止交付。Claude 入口使用相同检查工具。状态管理覆盖新增审查与修订文件、依赖失效和失败恢复。

## 验证

先写失败测试，覆盖配置优先级与冻结、默认配置变化、元数据不泄密、审查覆盖缺失/假引用/过期、修订上限、硬门修复后复审、恢复和既有三个 workflow 的兼容性。运行 Node 全套及相关 Python 回归，使用临时目录做无真实研究的 CLI 验证。
