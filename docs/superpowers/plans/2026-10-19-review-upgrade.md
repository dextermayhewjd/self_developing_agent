# 审查协议修复与旧内容复用

> 执行方式：本会话内直接实施，按测试驱动完成；用户已授权修复并要求复用原内容。

**目标：** 修复 reviewed_sources 返回范围不明确的问题，允许在研究、证据、方法和执行配置不变时显式升级审查代码。

**设计：** 改动前保存可重建旧全局指纹的源码快照、运行状态、输入清单和 Store HEAD。升级入口核对这些基线，只接受审查协议及其升级入口涉及的指定文件变化。在持有原运行锁时，由 state 写入新指纹和升级记录；保留所有研究产物、Store 历史和额度。正常续跑继续拒绝指纹不一致。

**实现范围：**

- `review-coordinator.mjs`、`review-contracts.mjs`：向审查明确传入唯一来源清单，动态限制合法来源及数量，继续执行现有完整性校验。
- `review-upgrade.mjs`：捕获基线、重建旧指纹、验证代码差异、输入与 Store 内容，生成兼容升级记录。
- `run_codex_workflow.mjs`、`state.mjs`：增加显式捕获/升级参数及持锁状态转换。
- 对应测试与操作文档：覆盖遗漏/额外来源、允许的审查变更、禁止的研究变更、报告/证据篡改、配置变化和重复升级。

**约束：** 不移除全局指纹检查；不改旧审查响应；不自动改变原始输入、报告、证据或额度。升级必须绑定精确旧指纹和 Store HEAD。没有基线的历史版本不猜测兼容。

## 重点验证

1. 方法文档、原始数据或底稿变更必须拒绝升级。
2. 候选稿或 Store HEAD 改变必须拒绝升级。
3. 模型、强度和报告参数变化必须拒绝升级。
4. 同一次升级重复执行不得重复改账本或消耗额度。
5. 正常无升级参数的续跑仍拒绝代码变化。
